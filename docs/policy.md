# 정책

이 문서가 정책의 원본(SoT)이다. 기획서와 다르면 이 문서를 따르고, 정책을 바꿀 때는 이 문서를 먼저 고친다. 다른 문서의 "정책 N"은 이 문서의 N장을 가리킨다. 용어는 [용어](GLOSSARY.md)를 따른다.

> 모든 기간·마감·일시는 KST 기준이다.

## 1. HP 기본

| 정책명 | 내용 |
| --- | --- |
| HP와 원화 환산 비율 | 1 HP = 1원 (1:1) |
| HP 종류와 지갑 내 구분 | **충전 HP**와 **수익 HP**로 구분한다. HP 간 전환은 불가하다. |
| HP 결제 시 차감 순서 | 수익 HP를 전액 사용한 후 충전 HP를 사용한다. 사용자는 차감 순서를 조정할 수 없다. |
| 반환 시 HP 종류 | 보류 HP를 반환할 때(구매 취소, 출연 거절·취소 등)는 차감했던 HP 종류와 금액 그대로 복원한다. 강의는 주문 항목마다 HP를 별도로 보류하고, 일부 항목을 취소·반환·지급할 때도 해당 항목의 보류분만 사용한다. 주문 전체 보류분에 대한 충전 HP 우선 반환·수익 HP 우선 지급 규칙은 두지 않는다. 예: 수익 HP 3,000 + 충전 HP 7,000으로 5,000 HP 강의 A·B를 구매하고 A에 수익 3,000 + 충전 2,000, B에 충전 5,000이 배분되었다면, A 취소 시 수익 3,000 + 충전 2,000을 반환하고 B 취소 시 충전 5,000을 반환한다. |

## 2. 충전 · 환불 · 환전

| 정책명 | 내용 |
| --- | --- |
| 최소 충전 금액 | 충전은 1,000원 단위로 한다. 최소 충전 금액은 1,000원이다. |
| 환불 대상 | 충전 HP 잔액이 0원을 초과하는 사용자 |
| 회원 상태와 충전·환불·환전 | 충전과 환전 신청은 정상 상태의 회원만 할 수 있다. 환불 신청은 정지된 회원도 할 수 있고(결제한 돈을 돌려받는 것이라 정지로 막지 않는다), 탈퇴한 회원은 할 수 없다. 정지·강등은 이미 발급된 로그인 토큰이 만료되기를 기다리지 않고 반영된다(7장 "역할 변경 반영"의 최대 15분 지연이 없다). 신청 취소와 조회는 회원 상태와 관계없이 할 수 있다. 회원이 탈퇴하면 지갑을 닫는다. 닫힌 지갑은 충전·환불·환전 신청과 새 결제(강의 구매·출연 요청의 HP 보류)를 받지 않고, 이미 생긴 보류의 반환과 수익 HP 지급은 받는다. 충전·수익 HP 잔액이나 처리 중인 환불·환전·충전이 있으면 지갑을 닫지 않아 탈퇴할 수 없다(#623). 닫힌 뒤 들어온 HP(보류 반환·수익 HP 지급)는 지갑에 남고, 회원이 30일 안에 복구해 지갑이 다시 열려야 환불·환전할 수 있다. 운영자는 잔액이 남은 닫힌 지갑을 지표로 확인한다. 복구 기한이 지나 회원 정보를 파기한 뒤에도 남은 잔액은 지갑에 그대로 남기고(돈 기록은 지우지 않는다), 운영자가 이 지표로 확인해 따로 처리한다(#594). 출연·강의의 반환·지급은 이 규칙을 따르지 않는다(5장 "정지된 회원의 출연도 응답·지급한다"). |
| 일부 사용한 충전 HP 환불 | 충전 HP 잔액만큼 언제든 부분 환불할 수 있다. 예: 100만 원 충전 → 30만 HP 사용 → 남은 70만 HP 환불 |
| 환전 대상과 단위 | 수익 HP 잔액이 1원 이상인 사용자. 환전은 1원 단위로 한다. 송금액이 0원인 환전(1원 신청)은 은행 송금 없이 정산 예정 시각에 완료한다. |
| 환전 신청과 송금 | 사용자가 직접 환전을 신청하면 신청 금액만큼 수익 HP를 보류한다. 세미 프로젝트는 관리자 승인 후 정산일 배치가 송금하며, 승인 전에는 회원이 취소할 수 있고 관리자가 거절하면 보류 HP를 반환한다. 신청일이 KST 1~9일이면 당월 10일, 10일 이후이면 다음 달 10일을 잠정 정산일로 정하고 토·일요일이면 다음 월요일로 보정한다. 공휴일은 반영하지 않는다. 잠정 정산일 00:00 KST 전에 승인되어야 해당 회차에 포함되며, 그 시각 또는 이후 승인되면 승인 시각 이후 첫 정산 회차로 이월한다. 정산 예정 시각이 지난 승인 건은 미처리분을 포함해 배치가 처리한다. 실제 은행 계좌 확인·송금은 구현하지 않았으며, local·test에서 Mock이 활성화된 경우에만 가상 송금을 실행한다. dev·prod에서는 송금을 건너뛴다. |
| 환전 신청 금액 보류 | 신청한 수익 HP는 즉시 보류해 결제에 쓸 수 없다. 승인 전 회원 취소 또는 관리자 거절 시 보류 전액을 반환한다. 가상 송금 성공 시 보류 HP를 확정 차감한다. 송금 결과 불명·처리 중·운영자 확인·확정 실패(FAILED) 상태에서는 보류를 유지하며, 관리자는 결과 재확인 또는 확정 실패 뒤 수동 재송금을 할 수 있다. 관리자가 최종 실패(FINAL_FAILED)로 종료할 때 보류한 수익 HP 전액을 반환한다. |
| HP 사용과 환불 순서 | FIFO: 충전 HP를 보류할 때마다 충전 건별 사용 예정 금액을 추적하고, 지급이 완료되면 해당 충전 원금을 실제 사용 |

환전 예시: 수익 HP 100만 중 50만을 신청하면 50만을 즉시 보류한다(사용 가능 50만). 관리자 승인 후 확정된 정산 회차에 Mock 가상 송금을 실행하며 수수료 5만을 뺀 예상 수령액은 45만 원이다. 승인 시점에 따라 다음 회차로 이월될 수 있고, 실제 현금은 이동하지 않는다.

## 3. 수수료 · 정산

| 정책명 | 내용 |
| --- | --- |
| 정산 대상 범위 | 인플루언서 이상 |
| 플랫폼 수수료율 | 10%로 한다. 송금액은 신청 금액의 90%에서 원 미만을 버린 금액이고, 수수료는 신청 금액에서 송금액을 뺀 금액이다. 예: 1,234 HP → 송금 1,110원, 수수료 124 HP |
| 수수료 공제 시점 | 수익 HP를 KRW로 환전할 때만 발생한다. |
| 수수료 수입 기록 | 환전 송금이 성공하면(송금액 0원 환전은 완료될 때) 공제한 수수료를 플랫폼 지갑에 수수료 수입으로 기록한다. 회원의 보류 차감액은 송금액(KRW)과 수수료 수입의 합과 같다. 송금 최종 실패·취소·거절은 보류 전액을 반환하므로 기록하지 않는다. 플랫폼 지갑은 관리자만 조회한다. |

## 4. 거래 중 HP 보류와 해제

출연료 지급은 방송 예정 일시 이후에만 발생한다. 단, 호스트 출연 취소 위약금은 취소 즉시 게스트 수익 HP로 지급한다.

| 거래 | 보류 시작 | 지급 조건 | 자동 지급 |
| --- | --- | --- | --- |
| 강의 | 결제 시 | 내용 다름 이의 제기 기간(구매일 다음 날부터 30일)이 끝나면 판매자 수익 HP로 지급 | 해당 없음 (항상 기간 경과 후 지급) |
| 출연 요청 | 출연 요청 발송 시 | 방송 예정 일시부터 확인 기간 안에 호스트가 확인(긍정 응답) → 지급. 불참(부정 응답)이면 전액 반환 | 출연 확인 기간이 지나면 자동 확인·지급 |
| 출연 모집 | 모집 글 게시 시 | 방송 예정 일시부터 확인 기간 안에 호스트가 출연자 별로 확인(긍정 응답) → 지급. 불참(부정 응답)이면 전액 반환 | 출연 확인 기간이 지나면 자동 확인·지급 |

| 정책명 | 내용 |
| --- | --- |
| 구매 확정 | 직접 확정, 첫 재생(재생 동의), 구매일 다음 날부터 7일 경과 중 먼저 오는 시점. 구매 확정 후에는 단순 변심으로 취소할 수 없다. 구매 확정은 지급 시점이 아니다. |
| 강의 지급 시점 | 구매 확정과 별개로, 내용 다름 이의 제기 기간(구매일 다음 날부터 30일)이 끝나야 판매자 수익 HP로 지급한다. 이의 제기가 접수된 건은 처리 결과에 따른다. 지급된 수익 HP는 환전을 신청하면 다음 정산일(매월 10일)에 송금된다. |
| 출연 확인 | 방송 예정 일시 이후 호스트가 출연 건마다 "확인" 또는 "불참"으로 응답한다. 확인하면 게스트에게 출연료를 지급하고, 불참이면 보류 HP 전액을 호스트에게 반환한다. 응답은 번복할 수 없다. 출연자가 2명 이상이면 각각 응답한다. |
| 출연 확인 기간 | 방송 예정 일시부터 7일(7 × 24시간)까지. 기간 안에 호스트가 응답하지 않으면 자동으로 출연을 확인하고 지급한다. |

강의 예시: 9/30 구매 → 10/7까지 단순 변심 취소 가능(구매 확정 전) → 10/30까지 내용 다름 이의 제기 가능 → 10/30 기간 종료 후 판매자 수익 HP 지급 → 11/9까지 환전 신청하면 11/10 정산일에 송금

출연 예시: 10/10 20:00 방송 → 10/17 20:00 전까지 호스트가 확인 또는 불참으로 응답 → 응답이 없으면 10/17 20:00 이후 자동 확인되어 게스트에게 지급 → 게스트가 환전을 신청하면 다음 정산일에 송금

## 5. 출연 거래

| 정책명 | 내용 |
| --- | --- |
| 참여 자격 | 출연 거래(요청·모집·지원·수락)에는 활동 중(ACTIVE)인 인플루언서 이상 회원만 참여할 수 있다. 일반 유저와 관리자는 참여할 수 없다. 지원한 뒤 정지·강등된 게스트의 지원은 수락할 수 없다. |
| 최저 출연료 | 1인당 20,000원 |
| 출연 요청 | 호스트가 게스트 1명을 지정해 출연료·방송 예정 일시·수락 기한을 담아 요청서를 보낸다. 수락 기한은 현재 이후, 방송 예정 일시 이전이어야 한다. 같은 호스트가 같은 게스트에게 응답을 기다리는 요청서가 있으면 새 요청서를 보낼 수 없다. 보내는 즉시 출연료만큼 호스트의 HP를 보류한다. |
| 출연 요청 응답 | 게스트는 수락 기한 전까지 수락하거나 거절할 수 있다. 수락하면 출연이 성립한다. 거절하거나, 호스트가 게스트 응답 전에 요청서를 취소하거나, 수락 기한이 지나면(만료) 보류 HP 전액을 호스트에게 반환한다. |
| 출연 모집 | 호스트가 1인당 출연료·모집 인원(1~10명)·모집 마감 일시를 정해 모집글을 올린다. 모집 마감 일시는 현재 이후, 방송 예정 일시 이전이어야 한다. 올리는 즉시 1인당 출연료 × 모집 인원만큼 호스트의 HP를 보류한다. 같은 호스트가 올릴 수 있는 모집글 수에는 제한이 없다. |
| 출연 모집 지원 | 게스트는 모집 중인 모집글에 한 번만 지원할 수 있다(메시지 선택). 호스트가 응답하기 전에는 지원을 취소할 수 있으며, 취소한 뒤에도 다시 지원할 수 없다. 정원이 차도 지원은 계속 받는다(출연 취소 요청으로 빈자리가 생길 수 있기 때문). |
| 지원 수락 (출연 성립) | 호스트가 지원을 수락하면 그 게스트와 출연이 바로 성립한다. 정원까지만 수락할 수 있다. 호스트가 거절한 지원은 미선정이 된다. |
| 모집 마감 | 모집 마감 일시가 되거나, 호스트가 그 전에 조기 마감하면 모집이 닫힌다(성립 인원이 0명이어도 조기 마감할 수 있다). 마감되면 대기 중인 지원은 미선정이 되고, 채우지 못한 자리만큼(미달 인원 × 1인당 출연료) 호스트에게 반환한다. 성립 인원이 0명이면 보류 HP 전액을 반환한다. 정원을 모두 채웠으면 HP 이동이 없다. |
| 등록 후 수정 | 제목·콘텐츠 설명·호스트 채널 URL만 수정할 수 있다. 요청서는 게스트 응답 전까지, 모집글은 모집 중이고 마감 일시 전까지 호스트만 수정할 수 있다. 출연료·인원·방송 예정 일시·기한은 수정할 수 없다. |
| 출연 취소 요청 (게스트) | 출연이 성립한 뒤 방송 예정 일시 전까지 게스트는 사유를 적어 호스트에게 출연 취소를 요청할 수 있다. 출연 1건당 최대 2회(거절된 뒤 1회 재요청)이며, 보낸 요청은 철회할 수 없다. 호스트가 수락하면 합의 취소, 거절하면 출연이 유지된다. 방송 예정 일시까지 호스트가 응답하지 않으면 자동 거절되어 출연이 유지된다. |
| 합의 취소 시 HP | 위약금은 없다. 출연 요청은 해당 출연료를 호스트에게 반환한다. 출연 모집은 모집 마감 전이면 보류를 유지하고 성립 인원에서 제외해 빈자리에 다른 지원자를 수락할 수 있게 하며, 다시 채우지 않으면 마감 때 함께 반환한다. 모집 마감 후면 해당 출연료를 호스트에게 반환한다. |
| 호스트 일방 취소 위약금 | 출연이 성립한 뒤 방송 예정 일시 전에 호스트가 일방적으로 취소하면, 출연료의 30%(원 단위 미만 버림)를 취소 즉시 게스트에게 지급하고 나머지는 호스트에게 반환한다. 취소된 자리는 다시 열지 않는다. 예: 출연료 20,000원 → 게스트 6,000원 지급, 호스트 14,000원 반환 |
| 출연 모집 전체 취소 | 호스트는 방송 예정 일시 전까지 모집 중이거나 마감된 모집글 전체를 취소할 수 있다. 성립한 출연마다 호스트 일방 취소 위약금을 적용하고, 대기 중인 지원은 미선정 처리하며, 채우지 않은 자리의 보류 HP는 호스트에게 반환한다. |
| 처리 중인 취소 요청이 있을 때의 일방 취소 | 게스트의 출연 취소 요청이 처리 중인 출연을 호스트가 일방 취소(또는 모집 전체 취소)하려 하면, 시스템이 호스트에게 한 번 더 확인을 받는다. 서버에서도 확인 여부를 검증한다. 확인하면 취소를 진행하고, 처리 중이던 취소 요청은 종료하며 위약금은 그대로 지급한다. |
| 출연 확인 · 불참 | 4장 "출연 확인"을 따른다. 게스트가 출연하지 않았으면 호스트는 출연 확인 기간 안에 불참으로 응답하고(사유 선택), 보류 HP 전액을 호스트에게 반환한다. 정지된 회원의 출연도 응답·지급한다. |
| 이의 제기 | 불참 판정 등 출연 결과에 대한 이의 제기는 고객센터 정책을 따른다. 출연 모듈은 이의 제기로 지급을 멈추지 않는다. |
| HP 보류 실패 · 지연 | 보류가 거절되면(잔액 부족 등) 요청서·모집글은 등록되지 않으며 그 사유를 그대로 안내한다. 보류 결과를 바로 알 수 없으면 등록을 보류 처리 중으로 두고, 시스템이 매분 다시 확인해 정리한다. |
| 반환 · 지급 실패 | 반환·지급·위약금 처리가 일시적으로 실패하면 시스템이 자동으로 다시 시도한다(최대 10회, 간격을 점점 늘림). 다시 보내도 결과가 같은 실패이거나 10회를 넘기면 관리자가 확인한다. 같은 처리는 여러 번 시도해도 한 번만 반영된다. |
| 입력 제한 | 제목 100자, 호스트 채널 URL(http/https) 255자, 콘텐츠 설명 5,000자, 예상 출연 시간 1~1,440분, 지원 메시지·취소 사유 500자 |

## 6. 강의

| 정책명 | 내용 |
| --- | --- |
| 강의 검수 | 기준은 관리자 재량이다. 등록한 강의는 검수 대기(비공개)로 시작하며, 관리자가 승인하면 공개·판매를 시작한다. 반려하면 사유를 남기고 판매자가 영상·자료를 수정한 뒤 다시 검수를 신청한다. 세미 프로젝트에서는 반려된 강의만 영상·자료를 수정할 수 있다. 검수 대기·판매 중에는 콘텐츠를 수정할 수 없으며, 판매 중 강의를 고치려면 삭제 후 재등록한다. 기존 구매자는 삭제된 기존 강의를 계속 시청한다. 승인본·수정본을 따로 관리하지 않는다. 제목·소개·가격·썸네일은 삭제 전이면 수정할 수 있고 재검수 대상이 아니다. |
| 강의 가격 | 1,000 HP 이상, 1,000 HP 단위로 정한다. 무료 강의는 없다. |
| 구매 제한 | 판매자는 자기 강의를 장바구니에 담거나 살 수 없다. 이미 보유한 강의(구매 취소·반환되지 않은 강의)는 다시 살 수 없다. |
| 첫 재생 (재생 동의) | 구매 확정 전에 영상을 재생하거나 자료를 내려받으려면, 먼저 "보면 구매가 확정되어 단순 변심으로 구매 취소할 수 없다"는 재생 동의를 받는다. 동의한 시점을 첫 재생으로 보고 구매를 확정한다. 동의 전에는 영상·자료를 제공하지 않는다. |
| 구매 취소 기간 · 조건 (단순 변심) | 구매 확정 전 (첫 재생(재생 동의) 전, 구매일 다음 날부터 7일 이내) |
| 내용 다름 이의 제기 기간 · 조건 | 구매일 다음 날부터 30일 이내 고객센터로 이의를 제기할 수 있다. 접수되면 해당 주문 항목의 지급을 멈추고 보류를 유지한다. 관리자가 인정하면 해당 항목에서 차감했던 HP 종류와 금액 그대로 구매자에게 반환한다. 기각하면 이의 제기에 따른 지급 중단을 해제하며, 즉시 지급하지 않고 원래 지급 예정 시각이 지난 뒤 지급 배치가 판매자 수익 HP로 지급한다. |
| 강의 삭제 | 판매자가 강의를 삭제하면 목록 노출과 신규 판매만 멈춘다. 기존 구매자는 계속 볼 수 있고, 지급은 예정대로 진행한다. |
| 리뷰 · 평점 | 구매 확정 후에만 쓸 수 있다. 이의 제기로 반환된 구매의 리뷰는 남기되 평균 평점에서 제외한다. |
| 판매자 탈퇴 · 자격 상실 | 판매 중이거나 검수 대기 중인 강의가 있으면 탈퇴할 수 없다. 강의를 삭제하면 탈퇴할 수 있고, 삭제한 강의도 기존 구매자는 계속 보며 지급은 예정대로 진행한다(강의 D75). 아직 지급되지 않은 판매 수익이 있어도 지급이 끝날 때까지 탈퇴할 수 없다. 인증된 인플루언서 자격을 잃는 경우에는 판매 중인 강의를 따로 처리하지 않는다. |

## 7. 회원 · 인증 · 데이터

| 정책명 | 내용 |
| --- | --- |
| 가입 · 로그인 | 구글 계정(소셜 로그인) 또는 이메일·비밀번호(비밀번호 로그인)로 가입·로그인한다. 구글은 첫 로그인 때 자동으로 가입된다. 가입하면 역할은 유저다. 같은 이메일로 두 방식에 모두 가입할 수 없다(계정 연결은 아직 없다). 로그인 상태는 access token(15분)과 refresh token(14일)으로 유지한다. |

| 이메일 인증 (#557) | 메일로 받은 6자리 인증 코드로 이메일 주인인지 확인한다. 용도는 이메일 가입과 비밀번호 재설정 두 가지이고, 코드와 인증 토큰은 용도마다 따로다(가입 토큰으로 재설정할 수 없다). 코드는 10분 동안 쓸 수 있고, 5번 틀리면 지워져 다시 받아야 한다. 확인하면 30분 동안 한 번 쓸 수 있는 인증 토큰을 준다. 코드를 받을 때 가입 여부는 알려 주지 않는다: 응답은 항상 같고 메일함에 가는 것만 다르다. 가입은 가입되지 않은 이메일이면 코드, 이미 가입된 이메일이면 "이미 가입된 이메일" 안내를 보낸다. 재설정은 비밀번호가 있는 정상 회원이면 코드, 구글로만 가입한 정상 회원이면 "구글로 로그인" 안내를 보내고, 없는 이메일·탈퇴·정지 회원에게는 보내지 않는다(재설정은 정상 회원만). 남용을 막으려고 용도와 상관없이 합쳐 같은 이메일은 1분에 한 번, 한 IP(IPv6는 /64)는 1시간 10통, 한 이메일은 하루 5통, 앱 전체는 하루 300통까지 보낸다(Gmail 하루 한도 약 500통 소진, 메일 폭탄, 코드 맞히기 방지). 누가 남의 이메일로 하루 5통을 다 쓰면 그날 그 회원은 재설정 코드를 받지 못한다(알려진 한계). 메일은 뒤에서 보내 응답 시간·응답이 메일을 보내는지와 상관없이 같다. 메일이 오지 않으면 1분 뒤 다시 받는다. 구글 가입·초기 계정·관리자가 만드는 관리자 계정·부하 시험 계정(아래 "부하 시험 회원 승급 예외"의 이메일 형식, 임시)은 이메일 인증을 거치지 않는다. 비밀번호 변경(로그인한 상태, 현재 비밀번호로 확인)도 거치지 않는다. 메일은 Gmail SMTP(`hapbang.noreply@gmail.com`)로 보낸다. 같은 이메일의 비밀번호 회원과 구글 회원을 하나로 잇는 계정 연동은 아직 정하지 않았다. |

| 역할 변경 반영 | 채널 인증·승급이 승인되면 다시 로그인하지 않아도 토큰을 재발급받으면 새 역할로 이용할 수 있다. 정지·강등은 재발급이 바로 막히고, 이미 발급된 토큰에는 최대 15분 뒤 반영된다. |
| 삭제 정책 (Hard Delete 금지) | 모든 데이터는 Soft Delete 한다. 회원 탈퇴 시 User도 Soft Delete 하고, 복구 기한(30일)이 지나면 회원을 식별할 수 있는 정보만 파기(마스킹)한다(#594). 복구 기한 안에 복구를 시도했는데 지갑을 다시 열지 못해 실패했으면 복구 기한과 파기를 7일 미룬다(회원 잘못이 아닌 장애). 파기 대상: 이메일·닉네임·프로필 이미지·OAuth 계정 정보·비밀번호 정보, 채널 이름·URL·식별자, 환전 계좌의 계좌번호·예금주. 남기는 것: 회원 행, 지갑·원장·충전·환불·지급·환전의 금액·상태·일시, 채팅 메시지·문의 본문(분쟁 확인용). 채팅·문의 작성자는 '탈퇴한 회원'으로 표시한다. |
| 파기 방법 (#594) | 회원 앱이 매일 10:30(운영 서버가 켜진 시간)에 복구 기한이 지나고 1시간이 더 지난 탈퇴 회원을 파기하고(기한 직전에 누른 복구가 끝나기 전에 파기하지 않게) `UserMaskedEvent`를 발행한다. 이메일은 지운다(빈 값끼리는 유일 제약에 걸리지 않아 겹치거나 선점될 일이 없다). 닉네임은 다른 앱에 복제되므로 `탈퇴회원#{회원ID}`로 바꾸고(`#`은 닉네임 규칙 밖 글자라 다른 회원이 이 닉네임을 쓸 수 없다), 구글 계정 ID·채널 이름·URL·식별자는 `withdrawn_{행 ID}`로 바꾼다. 그래서 같은 이메일·구글 계정·채널로 새로 가입·등록할 수 있다. 비밀번호 정보는 행을 남기고 해시를 지운다. 프로필 사진은 연결을 끊고, 그 회원 사진 폴더의 S3 파일(예전에 바꾼 사진 포함)을 모두 빈 파일로 덮어써 원본을 지운다(앱에는 S3 삭제 권한이 없다). 사진을 바꾸거나 내릴 때도 옛 파일을 바로 빈 파일로 덮는다. 복구 기한은 복구를 누른 시각으로 판단한다. 회원 앱 밖의 파기 대상(지갑의 환전 계좌 계좌번호·예금주, 출연의 호스트 채널 주소)은 `UserMaskedEvent`를 받은 앱이 지운다. 지갑은 끝난 환전의 계좌만 지우고 처리 중인 환전의 계좌는 송금이 끝날 때까지 남겨 운영자가 정리하며, 그때 지갑이 열려 있으면(복구 중 다시 열기가 늦게 처리된 경우) 닫는다(#674). |

## 8. 모집용 단체 채팅방 (2026-11-02 사용자 결정, 구현 전)

기존 1:1 동작은 유지한다. 모집용 단체방 설계·결정은 [채팅 설계 3·8장](../apps/chat-app/docs/final-design.md)에 있다. 세부(설계 Q31~Q38)는 2026-11-03 확정했다. 정원 숫자는 부하 시험 뒤 확정한다.

| 정책명 | 내용 |
| --- | --- |
| 생성 | 정상 등록된 모집 중인 출연 모집글의 호스트만 생성한다. HP 보류 처리 중·실패·모집 마감·모집 전체 취소인 모집글에는 새 방을 만들 수 없다. 제목은 모집글 제목을 따른다. 호스트 메시지 프로필에는 왕관을 표시한다. |
| 모집글과 방 | 동시에 사용하는 방은 모집글당 하나다. 호스트가 폐쇄하면 이전 방은 읽기 전용으로 남고, 생성 조건을 만족하면 새 ID의 방을 만들 수 있다. 이전 방이 자동 재개되는 것은 아니다. 일시 중지된 방은 현재 방으로 남아 새 방을 만들 수 없다. 자격 상실로 읽기 전용이 된 방은 현재 방이 아니다(설계 Q31·Q32). |
| 초대 후보 | 해당 모집글에 지원 이력이 있는 모든 회원(대기·수락·미선정·지원 취소 포함) 중 현재 채팅 가능한 회원이다. 호스트만 닉네임 부분 일치로 검색한다. 회원 ID는 사용자에게 드러내지 않으므로 검색어로 쓰지 않는다(2026-11-03 사용자 결정). 같은 닉네임이 여럿이면 모두 보여 준다. |
| 혼자 남은 방의 전송 | 사용 중인 모집용 단체방에서는 호스트 혼자 남아도 메시지를 보낼 수 있다(Q2, 2026-11-02). 기존 1:1의 상대 퇴장 전송 금지는 유지한다. |
| 초대와 부분 성공 | 호스트 초대로 즉시 참여한다. 여러 명 초대는 회원별로 성공·실패하며 실패자는 다시 검색할 수 있다. 중복 ID·이미 참여 중인 회원은 중복 처리·알림하지 않는다. 정원이 모자라면 요청 순서대로 빈자리를 채운다. 한 요청의 인원 상한과 같은 요청의 재시도 처리는 설계 Q34다. |
| 퇴장·강퇴·재입장 | 일반 참여자는 나갈 수 있고 호스트는 강퇴할 수 있다. 자진 퇴장·강퇴 후 모두 호스트 재초대로만 입장하며 이전 메시지는 보이지 않는다. 호스트는 나가기 대신 방을 폐쇄한다. |
| 정원 | 모집 인원과 별도로 현재 참여 중인 게스트를 센다(오프라인 포함, 퇴장·강퇴 제외, 호스트 별도). 500명은 부하 시험 후보 상한이며 지원 보장이 아니다. 정원·동시 연결·초당 전송 한도는 읽음 숫자를 포함한 부하 시험으로 확정한다. |
| 출연과 독립 | 채팅 초대·강퇴·퇴장은 출연 지원 수락·취소·HP 처리를 발생시키지 않는다. 모집 마감·전체 취소 후에도 기존 방의 대화·초대는 호스트가 폐쇄하기 전까지 유지한다. 새 방 생성 가능 여부와 구분한다. |
| 폐쇄·기록 조회 | 호스트 폐쇄는 읽기 전용 전환이다. 전원 퇴장시키지 않고, 나가지 않은 참여자는 전환 시각부터 30×24시간 동안 자기 가시 범위의 기록을 조회한다(그 시각에 도달하면 조회 불가). 읽기 전용 방에서도 읽음은 갱신되고 개별로 나갈 수 있다. 새 초대·강퇴는 할 수 없다. 호스트는 폐쇄한 뒤에만 자기 목록에서 나갈 수 있다. 개별 퇴장자는 그 전에도 다시 조회할 수 없다(설계 Q33). |
| 호스트 탈퇴·자격 상실 | 자격 상실 안내를 방에 남긴 뒤 읽기 전용으로 전환한다. 그 전환일부터 30일 뒤 참여자 조회를 만료한다(총 60일이 아님). 30일 안에 자격 회복·탈퇴 복구가 와도 기존 방은 재개하지 않고, 생성 조건을 만족하면 새 방을 만든다(설계 Q31). |
| 호스트 일시정지 | 일시적으로 사용을 중단하고 정지 해제 후 재개한다. 현재 회원 정지 기능은 추후 구현 대상이다. 중단 중에는 조회·읽음·나가기만 할 수 있고 전송·초대·강퇴는 할 수 없다. 일시 중지만으로 30일 조회 만료가 시작되지 않는다. 정지 중 탈퇴·자격 상실이나 폐쇄가 있으면 정지 해제로도 재개하지 않는다(설계 Q32). |
| 조회 기간 만료 | 30일 뒤 기록 삭제는 참여자에게 숨기는 Soft Delete/조회 만료다. 메시지 본문과 생명주기 기록은 물리 삭제하지 않으며 관리자가 계속 조회할 수 있다. 7장의 분쟁 확인용 보존 정책을 유지한다. |
| 메시지별 안 읽은 사람 수 | 일반 메시지 옆에 모든 참여자가 숫자를 보고 0이면 숨긴다. 발신자·늦게 초대돼 해당 메시지를 볼 수 없는 회원·퇴장/강퇴자는 제외한다. 재초대돼도 이전 메시지 집계에는 들어가지 않는다. 시스템 안내에는 숫자를 표시하지 않고 읽은 사람 명단도 노출하지 않는다. |
| 읽음 기준·복구 | 실제 화면 표시·활성 조건으로 읽고 한 기기에서 읽으면 그 회원이 읽은 것으로 처리한다. 수신 ACK와 읽음은 별개다. 역순·중복 갱신을 방어하고 연결 복구·갱신 유실 시 서버 조회로 보정한다. 방 목록의 안 읽은 메시지 수와 구분한다. |

## 팀 규칙 (기획서 밖)

기획서에는 없지만 팀이 지키는 규칙이다.

### 원장과 민감 정보

돈·HP 영역은 정합성이 최우선이다. 수정할 때는 아래 규칙을 먼저 확인한다.

- 잔액은 **원장(append-only)의 합**으로 계산한다. 지갑 잔액 컬럼은 캐시로만 쓴다.
- 원장 한 줄 = (지갑, HP 종류[충전/수익], 증감, 거래 유형, 참조 거래 ID, 시각).
- 환전 가능 여부는 원장의 HP 종류로 판별한다.
- 돈이 오가는 데이터는 **절대 Hard Delete 하지 않는다.** 원장은 삭제·수정하지 않고, 정정은 역분개로 한다.
- 결제키, 계좌 정보 등 민감 정보는 암호화해서 저장한다.
