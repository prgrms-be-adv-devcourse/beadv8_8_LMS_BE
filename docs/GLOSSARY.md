# 용어 (유비쿼터스 언어)

이 문서가 용어의 원본(SoT)이다. 기획서와 다르면 이 문서를 따르고, 용어를 바꿀 때는 이 문서를 먼저 고친다.

모든 문서·코드·API에서 아래 용어만 쓴다. 비슷한 뜻의 다른 말로 바꾸지 않는다. "피할 말"은 이 용어 대신 쓰면 다른 뜻이 되는 말이다. 기한·수치는 [정책](policy.md)에 있다.

## HP

| 용어 | 정의 / 구분 | 피할 말 |
| --- | --- | --- |
| HP | 플랫폼 재화(합 포인트). 강의 구매, 출연료 제공 등에 쓴다. 1 HP = 1원. 충전 HP와 수익 HP로 나뉜다. | |
| 충전 HP | 회원이 현금으로 충전한 HP (명세서의 "예치금"). **환불 가능, 환전 불가.** | |
| 수익 HP | 강의 판매·출연료가 지급되어 생긴 HP. **환전 가능, 환불 불가.** | |
| HP 충전 | 현금 → PG → 충전 HP로 바꾸는 과정 | |
| HP 결제 | 강의 주문·출연 요청·출연 모집에 HP를 쓰는 과정. 수익 HP를 먼저 쓰고, 부족하면 충전 HP에서 차감한다 | |
| HP 보류 | 거래 중인 HP를 묶어 두는 것. 거래가 확정되면 지급, 거절·취소·만료·불참이면 반환한다 | |
| 지급 | 보류 HP를 받는 쪽(판매자·게스트)의 수익 HP로 옮기는 것. 수수료 없음. 강의는 내용 다름 이의 제기 기간이 지난 뒤, 출연은 출연 확인 때 지급한다 (호스트 출연 취소 위약금은 일방 취소 즉시) | 정산 |
| 반환 | 보류 HP를 결제한 회원에게, 차감했던 HP 종류 그대로 되돌리는 것 | 환불 |
| HP 작업 | 보류·반환·지급·위약금을 Billing에 요청하는 작업 한 건의 기록. 실패하면 자동으로 다시 시도하고, 다시 보내도 같은 실패이거나 횟수를 넘기면 자동 처리를 멈추고 관리자가 확인한다 | |

## 강의

| 용어 | 정의 / 구분 | 피할 말 |
| --- | --- | --- |
| 구매 확정 | 구매자가 더 이상 단순 변심으로 취소할 수 없게 되는 시점. 직접 확정·첫 재생(재생 동의)·자동 구매 확정 기한 중 먼저 오는 것. **지급 시점과 다르다** | |
| 재생 동의 | 구매 확정 전 영상 재생·자료 다운로드 전에, 보면 구매가 확정된다는 데 동의하는 것. 동의한 시점이 "첫 재생"이며 구매가 확정된다. 동의 전에는 영상·자료를 제공하지 않는다 | |
| 구매 취소 | 구매 확정 전 주문 취소 → 보류 HP 반환. **환불과 다르다.** | 환불 |
| 구매 취소 처리 중 | 구매 취소를 요청해 보류 HP를 반환하는 중인 상태. 요청한 순간부터 시청할 수 없고, 반환이 끝나야 구매 취소다 | |
| 반환 처리 중 | 내용 다름 이의 제기가 인정되어 보류 HP를 반환하는 중인 상태. 시청할 수 없고 리뷰는 공개 목록·평점에서 빠진다. 반환이 끝나야 반환이다 | |
| 지급 처리 중 | 지급 예정 시각이 지나 보류 HP를 판매자에게 지급하는 중인 상태. 구매 확정 뒤라 계속 시청할 수 있고, 구매 취소·이의 제기는 할 수 없다 | |
| 장바구니 | 구매 전 강의를 담아 두는 곳. 서버에 저장하고, 강의만 담는다 | |
| 주문 | 장바구니나 바로 구매로 만든 구매 단위 (바로 구매 = 강의 1개 주문) | |
| 결제 처리 중 | 주문 직후 강의마다 HP 보류 결과를 기다리는 상태. 주문 내역에 보이지만 시청할 수 없고, 같은 강의를 다시 살 수 없다. 모든 보류가 성공하면 구매 완료다 | 보류 처리 중(출연 용어) |
| 결제 취소 처리 중 | 주문한 강의 하나 이상의 HP 보류가 거절되어, 이미 성공한 보류를 반환하는 중인 상태 | 환불, 롤백 |
| 결제 실패 | 주문한 강의의 HP 보류가 거절되었고, 묶여 남은 HP가 없음이 확인된 상태. 주문은 지우지 않고 주문 내역에 남는다. 같은 강의를 다시 살 수 있다 | 보류 실패(출연 용어) |
| 보유 | 구매자가 같은 강의를 다시 살 수 없는 상태. 결제 처리 중부터 지급 뒤까지이고, 결제 실패·구매 취소·반환되면 끝난다. **시청 가능과 다르다** | |
| 시청 가능 | 구매자가 강의 영상·자료를 볼 수 있는 상태. 구매 완료부터이고 구매 취소·반환되면 끝난다. 구매 확정 전에는 재생 동의가 필요하다 | |
| 내용 다름 이의 제기 기간 | 구매자가 강의 내용이 소개와 다르다고 이의를 제기할 수 있는 기간. 접수되면 지급을 멈추고, 관리자 판단에 따라 반환하거나 지급한다 | |

## 현금화

| 용어 | 정의 / 구분 | 피할 말 |
| --- | --- | --- |
| 환불 | 충전 HP를 PG로 현금화하는 것. **구매 취소와 다르다.** | 구매 취소, 반환 |
| 환전 | 수익 HP를 수수료 공제 후 KRW로 현금화하는 것. 신청하면 수익 HP를 보류하고, 관리자 승인 후 확정된 정산 회차에 처리한다. 세미 프로젝트는 local·test의 Mock 가상 송금이며 실제 현금은 이동하지 않는다 | 정산 |
| 환전 송금 | 관리자가 승인한 환전 건의 예상 KRW를 Mock 은행 API로 가상 송금하고 결과를 반영하는 것. 승인된 환전을 정산일 배치가 처리한다. 실제 계좌 실명 확인·은행 송금은 하지 않고, Mock이 켜진 local·test에서만 실행한다 (dev·prod는 송금 생략) | |
| 정산 | 지급과 환전을 통틀어 부르는 말 (명세서 대응 용어). 별도 모듈은 없고 지갑 모듈이 처리한다. 개별 행위에는 "지급", "환전"을 쓴다 | |
| 정산일 | 신청된 환전 건을 모아 KRW로 송금하는 날. 회차 계산은 [정책](policy.md) 2장 | |

## 출연

| 용어 | 정의 / 구분 | 피할 말 |
| --- | --- | --- |
| 호스트 | 개인방송을 진행하며 출연자를 찾는 쪽 | |
| 게스트 | 호스트 방송에 출연하는 쪽 | |
| 출연 요청 | 호스트가 특정 게스트 1명에게 보내는 요청. 보낼 때 출연료만큼 HP를 보류한다 | |
| 수락 기한 | 게스트가 출연 요청에 응답해야 하는 시각. 방송 예정 일시보다 앞이고, 지나면 만료된다 | |
| 만료 | 수락 기한까지 게스트가 응답하지 않아 요청이 끝난 것. 보류 HP 전액을 반환한다 | |
| 응답 전 취소 | 게스트가 응답하기 전에 호스트가 요청서를 거두는 것. 보류 HP 전액을 반환한다 | |
| 출연 모집 | 호스트가 다수 게스트를 공개 모집하는 것. 1인당 출연료 × 모집 인원만큼 HP를 보류한다 | |
| 지원 | 게스트가 모집글에 출연을 신청하는 것. 모집글당 1회이고, 정원이 차도 지원은 받는다 | |
| 지원 취소 | 호스트가 응답하기 전에 게스트가 지원을 거두는 것. 취소 후 다시 지원할 수 없다 | |
| 지원 수락 | 호스트가 지원을 받아들이는 것. 수락하는 순간 그 게스트와 출연이 성립한다. 정원까지만 가능하다 | |
| 미선정 | 호스트가 거절했거나, 모집이 마감될 때 대기 중이던 지원 | |
| 모집 마감 | 모집 마감 일시가 되어 모집이 닫히는 것 (기한 마감). 채우지 못한 자리만큼 반환하고, 성립 0명이면 전액 반환한다 | |
| 조기 마감 | 호스트가 모집 마감 일시 전에 직접 모집을 닫는 것. 처리는 기한 마감과 같고, 성립 0명이어도 할 수 있다 | |
| 출연 성립 | 출연 거래가 맺어진 시점. 요청은 게스트 수락, 모집은 호스트의 지원 수락. 성립 후 호스트가 취소하면 위약금이 생긴다 | |
| 출연 | 성립한 거래 한 건 (게스트 1명 = 1건). 출연료·방송 예정 일시는 성립 시점 값으로 고정한다 | |
| 출연 취소 요청 | 출연 성립 후 방송 예정 일시 전에 **게스트**가 호스트에게 출연 취소를 요청하는 것. 사유가 필수이고, 횟수 제한이 있으며, 철회할 수 없다 | |
| 합의 취소 | 호스트가 출연 취소 요청을 수락해 위약금 없이 출연이 취소된 것. **호스트 일방 취소와 다르다** | 호스트 일방 취소 |
| 자동 거절 | 방송 예정 일시까지 호스트가 출연 취소 요청에 응답하지 않아 거절된 것. 출연은 유지된다 | |
| 호스트 일방 취소 | 출연 성립 후 방송 예정 일시 전에 호스트가 출연을 취소하는 것. 위약금을 지급한다 | 합의 취소 |
| 호스트 출연 취소 위약금 | 호스트 일방 취소 때 게스트에게 주는 금액. 출연료의 일부를 게스트에게 지급하고 나머지는 호스트에게 반환한다 | |
| 모집 전체 취소 | 호스트가 방송 예정 일시 전에 모집글 전체를 취소하는 것. 성립한 출연마다 일방 취소(위약금)로 처리하고, 빈자리는 반환한다 | |
| 출연 확인 | 방송 후 호스트가 출연을 인정해 게스트에게 지급하는 것. 호스트 확인 또는 출연 확인 기간 경과 시 자동 확인 | |
| 불참 | 게스트가 출연하지 않았다는 호스트의 응답. 보류 HP 전액을 호스트에게 반환하고, 번복할 수 없다 | |
| 출연 확인 기간 | 호스트가 확인 또는 불참으로 응답할 수 있는 기간. 지나면 자동 확인한다 | |
| 보류 처리 중 | 등록 직후 HP 보류 결과를 기다리는 상태. 목록·상세에 보이지 않고, 시스템이 주기적으로 다시 확인한다 | |
| 보류 실패 | 잔액 부족 등으로 HP 보류가 거절된 상태. 등록되지 않는다 | |

## 회원과 역할

| 용어 | 정의 / 구분 | 피할 말 |
| --- | --- | --- |
| 비회원 | 로그인하지 않은 방문자. 강의 목록만 조회할 수 있다. 모집글 목록·상세와 인플루언서 목록·프로필은 로그인이 필요하다 | |
| 유저 | 일반 회원 (가입 시 기본 역할). 강의 구매만 가능하고 강의 등록·판매는 불가. 채널 인증을 신청할 수 있다 | |
| 인플루언서 | 채널 인증(치지직)을 마친 회원. 출연료 수령 가능, 강의 등록 불가 | |
| 인증된 인플루언서 | 관리자 승급 심사를 통과한 인플루언서. 강의 등록·판매 가능 | |
| 관리자 | 채널 인증 심사, 승급 심사, 강의 검수, 강의 내용 다름 이의 제기 판단, 고객센터 문의 답변을 하는 운영자. 거래 당사자가 되지 않는다 | |
| 소셜 로그인 | 외부 계정으로 가입·로그인하는 것. 지금은 구글만 지원한다. 치지직 연동은 로그인이 아니라 채널 인증이다 | |
| 회원 상태 | 회원의 이용 가능 상태: 정상·정지·탈퇴. 역할과 별개로 관리한다 | |
| 정지 | 관리자 조치로 이용이 제한된 상태 (추후 구현) | |
| 탈퇴 | 회원이 탈퇴한 상태. 일정 기간 뒤 개인정보를 마스킹하고, 그 전에는 복구할 수 있다 (탈퇴 기능 보류, 마스킹은 최종 프로젝트) | |
| 채널 인증 | 치지직 채널을 연동해 본인 채널임을 확인하고 인플루언서가 되는 절차. 유저만 신청할 수 있다 | |
| 채널 인증 상태 | 등록 → (승인 요청) → 승인 / 반려. 반려되면 다시 승인 요청할 수 있다 | |
| 자동 승인 | 팔로워 수가 기준 이상이면 관리자 심사 없이 채널을 바로 승인하는 것. 기준 미달이면 등록만 되고, 승인 요청 후 관리자가 심사한다 | |
| 채널 인증 심사 | 기준 미달 채널의 승인 요청을 관리자가 승인하거나 반려하는 것. 승인되면 유저 → 인플루언서 | |
| 팔로워 수 갱신 | 등록된 치지직 채널의 팔로워 수를 매일 다시 조회해 저장하는 것. 정상 회원의 채널만 대상이다 | |
| 승급 신청 / 승급 심사 | 인플루언서가 인증된 인플루언서가 되려고 신청하고, 관리자가 승인·반려하는 것. 승인되면 인플루언서 → 인증된 인플루언서 | |

## 채팅

### 엔티티

| 용어 | 정의 / 구분 | 피할 말 |
| --- | --- | --- |
| 채팅 회원 | 회원 이벤트로 채팅 모듈에 복제한 회원 정보 (원본 회원 ID·닉네임·역할·상태). 정상 상태의 인플루언서·인증된 인플루언서·관리자만 채팅할 수 있다. 탈퇴 회원은 "탈퇴한 회원"으로 표시한다 | |
| 1:1 채팅방 | 두 회원의 대화를 묶는 방. 같은 두 회원의 종료되지 않은 방은 하나만 유지한다. 두 사람 모두 퇴장하면 종료되고 다시 활성화하지 않으며, 이후 대화는 새 방을 만든다 | |
| 단체 채팅방(그룹 채팅방) | 여러 회원이 함께 대화하는 방. 2026-10-29 사용자 결정으로 이번 채팅 고도화의 설계·구현 범위에 포함한다. 현행 구현은 1:1이며, 단체 채팅의 세부 정책과 API는 [채팅 설계](../apps/chat-app/docs/final-design.md) 3·8장에서 확정한다 | |
| 채팅방 참여자 | 특정 회원의 입장·퇴장 상태, 메시지 조회 시작점, 읽음 위치를 관리하는 참여 정보. 이번 고도화에는 누적 수신 위치도 추가한다. 방·회원당 하나이고 재입장 때 같은 정보를 갱신한다 | |
| 채팅 메시지 | 방 안에 남기는 일반 대화·시스템 안내·출연 알림 한 건. 방 안의 순번으로 순서를 정한다. 회원이 보내는 일반 메시지 본문은 공백 불가, 최대 2,000자 | |
| 채팅방 생명주기 기록 | 방 생성·참여·퇴장·재입장·종료 사실을 행위자와 시각으로 남긴 기록. 추가만 하고 수정·삭제하지 않으며, 메시지와 별도로 보존한다 | |

### 핵심 값

| 용어 | 정의 / 구분 | 피할 말 |
| --- | --- | --- |
| 1:1 활성 대화 식별 키 | 두 회원 ID를 작은 값:큰 값 순서로 결합한 문자열 (예: `3:10`). 같은 두 회원의 활성 방 중복을 막고, 방이 종료되면 비운다 | |
| 방의 마지막 순번 / 메시지 순번 | 방에서 발급한 마지막 순번 / 각 메시지가 받은 방 안의 순번. 방을 잠근 상태에서 1씩 발급한다. 메시지 DB ID와 다르다 | |
| 메시지 조회 시작 순번 | 참여자가 볼 수 있는 첫 메시지의 방 순번. 재입장 때 이후 순번으로 옮겨 이전 메시지를 숨긴다. 메시지는 삭제하지 않으며 관리자 기록 조회에는 남는다 | |
| 참여 세대 | 같은 회원의 첫 참여와 이후 재입장을 구분하는 번호. 처음 1, 재입장마다 1 증가. 늦게 도착한 옛 퇴장 요청은 무시한다. JPA 낙관적 락 버전과 다르다 | |
| 마지막 수신 확인 순번 | 현재 참여 세대에서 어느 한 클라이언트가 자신에게 보이는 메시지를 해당 위치까지 빠짐없이 반영했다고 보고한 누적 순번. 2026-10-29 사용자 결정으로 추가할 목표 값이며 확인 전에는 미확인(NULL)이다. 읽음·서버 발행 완료·모든 기기의 수신을 뜻하지 않는다. [채팅 설계](../apps/chat-app/docs/final-design.md) 4.4를 따른다 | |
| 마지막 읽은 메시지 순번 | 화면에 보여 준 메시지 중 마지막으로 읽은 위치. 줄어들지 않고 방의 마지막 순번을 넘지 않는다. 입장·재입장 때 당시 마지막 순번으로 시작한다 | |
| 클라이언트 전송 ID | 클라이언트가 메시지에 붙이는 선택적 재전송 식별자 (최대 64자). 같은 방·발신자·참여 세대 안에서 같은 ID로 다시 보내면 본문이 달라도 기존 메시지를 돌려준다. 재입장 때 이전 전송 ID를 비운다 | |
| 출연 알림 대상 ID | 출연 요청 도착이면 요청서 ID, 모집 지원 도착이면 지원 ID. 알림 종류와 함께 해석하고, 출연 모듈과 FK로 연결하지 않는다 | |
| 출연 알림 상위 대상 ID | 모집 지원 알림이 가리키는 모집글 ID. 요청 도착 알림에는 없다 | |
| 안 읽은 메시지 수 | 내 조회 시작 순번 이상이고 마지막 읽은 순번을 넘는, 다른 회원이 보낸 삭제되지 않은 메시지 수. 조회 때 계산하고 시스템 안내 메시지도 조건에 맞으면 포함한다 | |
| 회원 원본 버전 / 복제본 락 버전 | 마지막으로 반영한 원본 회원 버전 / 복제본 행의 동시 갱신을 막는 버전. 늦거나 중복된 회원 이벤트는 원본 버전으로 거른다 | |

### 종류와 상태

| 용어 | 정의 / 구분 | 피할 말 |
| --- | --- | --- |
| 1:1 채팅방 (유형) | 두 회원이 참여하는 직접 대화 유형. 지금 지원하는 채팅방 유형은 이것 하나다 | |
| 진행 중인 채팅방 | 참여자가 한 명 이상 남아 있는 종료되지 않은 방. 두 사람 모두 참여 중이라는 뜻은 아니다. 상대가 나갔으면 새 일반 메시지를 보낼 수 없다 | |
| 종료된 채팅방 | 두 사람 모두 퇴장해 종료된 방. 다시 활성화하지 않는다 | |
| 일반 메시지 | 회원이 직접 작성해 보내는 대화 메시지 | |
| 시스템 안내 메시지 | 퇴장·재입장을 알리려고 서버가 만드는 메시지. 발신자는 해당 행위자 회원으로 기록한다 | |
| 출연 알림 메시지 | 출연 모듈의 이벤트를 받아 서버가 남기는 메시지. 알림 종류와 대상 ID로 어떤 출연 건인지 구분한다 | |
| 출연 요청 도착 | 호스트가 보낸 출연 요청을 게스트에게 알리는 종류. 호스트·게스트의 1:1 방에 저장한다 | |
| 출연 모집 지원 도착 | 게스트의 모집 지원을 호스트에게 알리는 종류. 같은 종류·대상 알림은 중복 저장하지 않는다 | |
| 채팅방 생성 / 참여자 입장 / 참여자 퇴장 / 참여자 재입장 / 채팅방 종료 | 채팅방 생명주기 기록의 종류. 퇴장해도 메시지는 삭제하지 않고, 남은 참여자에게 시스템 안내를 보낸다 | |
| 관리자 타임라인의 기록 항목 / 메시지 항목 | 관리자 통합 조회에서 생명주기 기록과 메시지를 구분하는 값. 같은 시각이면 기록을 먼저 정렬하고, 시각·종류·ID 커서로 함께 페이지 처리한다 | |
| 실시간 새 메시지 알림 | 새 메시지가 왔다는 사실을 받는 사람에게 WebSocket으로 전달하는 알림. DB에 저장하는 출연 알림 종류와 다르다 | 출연 알림 |
