# S3 (파일 업로드)

강의·출연·회원 파일(사진·영상)을 S3 버킷 1개에 둔다. **업로드는 서버 경유**(브라우저 → Envoy Gateway → app → S3)이고, **조회는 Presigned GET**으로 브라우저가 S3에서 직접 받는다.

> 공개 레포다. 버킷 이름, 계정 ID, ARN, 인스턴스 ID, 발급된 Presigned URL을 레포·PR·이슈에 쓰지 않는다. 아래 `<BUCKET>` 등은 자리표시자다.

## 구조

```
업로드  브라우저 ── (1) 파일 정보 등록 ──────────────▶ app ── fileId (PENDING)
           └──── (2) PUT /api/v1/{모듈}/files/{id}/content ─▶ Envoy ─(버퍼링 없이)─▶ app ─(스트리밍 PutObject)─▶ S3
조회    브라우저 ── (1) 조회 URL 요청 ──▶ app ── Presigned GET 발급(서명만)
           └──── (2) GET <Presigned URL> ──────────────────────────────────────────────▶ S3
```

| 항목 | 값 |
| --- | --- |
| 버킷 | 1개, 서울 리전. 퍼블릭 액세스 전부 차단, ACL 비활성화, SSE-S3 기본 암호화, 버킷 정책 없음 |
| key | `<환경>/<모듈 key>`. 예: `prod/lecture/LECTURE_THUMBNAIL/<uuid>`. 모듈은 `lecture/...`만 넘기고 환경 prefix는 `global/storage`가 붙인다. DB에는 모듈 key를 저장한다 |
| 환경 prefix | prod `prod/`, 로컬 `local/`. `dev/`는 기존 dev 서버가 쓰던 prefix다(dev 서버는 2026-10-30 제거, #440) |
| 업로드 | 서버 경유. `S3FileStorage.upload(key, contentType, contentLength, InputStream)` |
| 조회 | 버킷을 공개하지 않으므로 보여 줄 때마다 Presigned GET을 발급한다. 만료는 호출 모듈이 용도별로 정한다(`presignDownload(key, expiry)`, 최대 7일). 브라우저에서 열지 않고 파일로 내려받게 하려면 `presignDownload(key, expiry, 파일명)`을 쓴다(`Content-Disposition: attachment`가 서명에 포함되고 한글 파일명은 `filename*=UTF-8''…`로 들어간다, #125) |
| 서버 자격 증명 | EC2 인스턴스 역할. **액세스 키를 만들지 않는다**([security.md](security.md)) |

## 왜 서버 경유인가 (#106)

인스턴스 역할로 서명한 Presigned **PUT**을 EC2 밖(사용자 PC·브라우저)에서 쓰면 `403 AccessDenied`가 난다. 같은 URL을 EC2 안에서 쓰면 성공하고, Presigned **GET**은 밖에서도 성공한다.

- IAM 역할 정책·버킷 정책·서명·만료는 원인이 아니다(정책 시뮬레이터 허용, EC2에서 같은 요청 성공).
- 계정이 AWS Organizations에 속해 있어, 인스턴스 자격 증명이 밖에서 쓰기에 쓰이는 것을 막는 조직 정책(SCP/RCP, 데이터 경계)으로 추정한다. 정책 원문은 조회 권한이 없다.
- 다른 역할을 AssumeRole해서 서명하면 피할 수 있다고 알려져 있지만, 조직 보안 장치를 우회하는 것이므로 쓰지 않는다.
- 로컬 S3Mock은 서명·권한을 검사하지 않아 이 문제가 드러나지 않는다.

## 업로드 규칙 (모든 모듈 공통)

- 경로: **`PUT /api/v1/{모듈}/files/{id}/content`**. 요청 본문이 파일 그대로다(multipart 아님). `Content-Type`은 파일 형식이다.
- Envoy는 이 경로의 **PUT**에만 본문 상한·버퍼링 없이 긴 timeout(전체 30분, stream idle 60초)을 준다. 다른 메서드와 등록된 앱의 일반 `/api/` route는 본문 1MiB, 30초다. 등록되지 않은 `/api/**`는 `api-not-found` route가 404로 응답한다([gateway.md](gateway.md#본문연결grafanatrace)).
- 형식·크기 검사는 앱이 한다. Envoy는 같은 검사를 다시 하지 않는다. 앱은 `FormContentFilter`를 끈다(`spring.mvc.formcontent.filter.enabled: false`). 이 필터는 PUT·PATCH·DELETE의 `application/x-www-form-urlencoded` 본문을 인증 전에 전부 메모리로 읽기 때문에, 2GB를 받는 경로에서는 로그인 없이도 앱을 OOM으로 죽일 수 있었다(#107). 그래서 PUT·PATCH·DELETE API는 form 본문 파라미터를 쓰지 않는다(쿼리 문자열은 그대로 된다).
- **`Content-Length`가 필요하다.** chunked 요청은 앱이 길이를 몰라 거부한다.
- 앱은 `HttpServletRequest.getInputStream()`을 그대로 `S3FileStorage.upload`에 넘긴다. 본문을 메모리나 디스크에 모으지 않는다.
- 업로드 중 배포로 앱이 재시작되거나 연결이 끊기면 처음부터 다시 올린다(이어 올리기 없음). 실패하면 객체가 생기지 않는다.
- 업로드 본문은 DB 트랜잭션 밖에서 읽고, 검사·상태 변경만 짧은 트랜잭션으로 나눈다(강의 `FileContentUploadUseCase`, D25). 본문을 읽는 동안 DB 연결을 잡고 있지 않기 위해서다.

### 구현 근거 (AWS SDK 2.55 / `url-connection-client`)

| 항목 | 내용 |
| --- | --- |
| 메모리 | `UrlConnectionHttpClient`는 `Content-Length`가 있으면 `setFixedLengthStreamingMode`로 보내 본문을 모으지 않는다. `RequestBody.fromInputStream(in, length)`만 쓴다(길이 없는 `fromContentProvider`는 전체를 버퍼링한다) |
| 재시도 | 요청 본문은 되감을 수 없다. SDK가 재시도하면 끊긴 지점부터 이어 보내거나 `mark/reset` 오류로 원래 오류를 가린다. **업로드 요청만 재시도를 끈다**(`AwsRetryStrategy.doNotRetry()`, `S3FileStorageTest`로 확인) |
| 전송 방식 | 서버(HTTPS)는 `UNSIGNED-PAYLOAD` 본문, 로컬 S3Mock(HTTP)은 `aws-chunked` 서명 청크로 보낸다. 로컬 테스트가 서버 경로를 대신하지 못하므로 EC2 k3s에서 확인한다 |
| 크기 | 단일 PutObject 한도는 5GB. 2GB는 multipart 업로드 없이 된다 |
| 실측 | 힙 256MB에서 512MB·2GB 업로드 시 업로드 중 힙 최대 사용 75MB (`./gradlew :global:largeUploadTest`, 2026-10-13) |

## 앱 설정

| 설정 | 위치 | 값 |
| --- | --- | --- |
| `hapbang.storage.s3.bucket` | 앱 Secret `S3_BUCKET`(SealedSecret) → `application-prod.yaml` | 버킷 이름 (레포에 쓰지 않는다) |
| `hapbang.storage.s3.key-prefix` | `application-<env>.yaml` | `prod` / `local` |
| `hapbang.storage.s3.region` | `application.yaml` | `ap-northeast-2` |
| `hapbang.storage.s3.endpoint` | `application-local.yaml`만 | S3Mock 주소. 비어 있으면 실제 S3 |

`S3_BUCKET` 추가·변경 절차는 [env-vars.md](env-vars.md)를 따른다.

## AWS 설정 (AWS 담당자)

### 버킷 CORS

버킷 → 권한 → CORS(Cross-Origin 리소스 공유). 브라우저는 조회(GET)만 S3에 직접 한다. 업로드는 서버 경유라 `PUT`이 필요 없다.

```json
[
  {
    "AllowedOrigins": ["https://<prod 도메인>", "https://<dev 도메인>", "http://localhost:5173"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3000
  }
]
```

### EC2 인스턴스 역할

IAM → 역할 → 역할 생성(AWS 서비스 / EC2) → 인라인 정책(JSON) → EC2 → 작업 → 보안 → IAM 역할 수정

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ObjectReadWrite",
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject"],
      "Resource": ["arn:aws:s3:::<BUCKET>/dev/*", "arn:aws:s3:::<BUCKET>/prod/*"]
    },
    {
      "Sid": "ListForHead404",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::<BUCKET>",
      "Condition": { "StringLike": { "s3:prefix": ["dev/*", "prod/*"] } }
    }
  ]
}
```

- `HeadObject`라는 IAM 권한은 없다. HEAD는 `s3:GetObject`로 판정된다.
- `s3:ListBucket`이 없으면 없는 객체 HEAD가 404 대신 403이 된다. 업로드 완료 확인이 404를 기대하므로 같은 prefix로 준다.
- 업로드는 서버가 역할로 직접 `PutObject` 한다. Presigned GET은 발급한 쪽(서버 역할)의 권한으로 동작하고, 역할의 임시 자격 증명이 만료되면 URL도 만료 전에 끝날 수 있다.
- `DeleteObject`는 주지 않는다(Soft Delete).
- 두 node가 같은 인스턴스 역할을 쓰므로 IAM으로 앱이나 환경을 나눌 수 없다. prefix 분리는 정리용이다. 정책의 `dev/*`는 dev 서버를 지운 뒤에도 남아 있다.

### 인스턴스 메타데이터

EC2 → 작업 → 인스턴스 설정 → 인스턴스 메타데이터 옵션 수정: **IMDSv2 필수, 홉 제한 2**.
홉 제한이 1이면 pod 안에서 역할 자격 증명을 받지 못한다. k3s에서는 IMDS egress를 member·appearance·lecture pod에만 허용한다([gateway.md](gateway.md#본문연결grafanatrace)).

## 확인 (서버)

서버에 AWS CLI가 없으므로 컨테이너로 실행한다. `ubuntu`로 접속한다.

```bash
B=<BUCKET>
A="docker run --rm -e AWS_DEFAULT_REGION=ap-northeast-2 -v /tmp:/tmp amazon/aws-cli"
$A sts get-caller-identity                                  # Arn에 assumed-role/<역할 이름>
echo hello > /tmp/t.txt
$A s3 cp /tmp/t.txt s3://$B/dev/check.txt                   # 성공
$A s3api head-object --bucket $B --key dev/check.txt        # ContentLength 6
$A s3api head-object --bucket $B --key dev/none.txt         # 404 Not Found
$A s3 cp /tmp/t.txt s3://$B/other/check.txt                 # AccessDenied (정상)
```

확인한 객체는 역할에 삭제 권한이 없으므로 콘솔(S3 → 버킷 → 객체 → 삭제)에서 지운다. 출력된 Presigned URL은 어디에도 붙여 넣지 않는다.

### 업로드 경로 (Gateway)

Envoy의 업로드 route 검증은 [gateway.md](gateway.md)의 검증 기록을 따른다. 업무 앱을 배포한 뒤 실제 S3 2GiB 업로드를 확인한다(#372 남은 범위).

## 로컬 개발

- 기본은 `docker/compose.yaml`의 **S3Mock**이다. 앱을 실행하면 함께 뜨고 버킷(`hapbang-local`)이 자동으로 만들어진다. 계정·키가 필요 없다.
- S3Mock은 CORS를 모두 허용하고, **서명·만료·권한을 검사하지 않는다.** 권한·만료 동작은 EC2 k3s에서 확인한다.
- 올린 파일은 `s3mock-data` 볼륨에 남는다. 지우려면 `docker compose -f docker/compose.yaml down -v`(DB 볼륨도 함께 지워진다).
- 실제 S3로 확인해야 하면(AWS 담당자만): `S3_ENDPOINT=`(빈 값), `S3_BUCKET=<BUCKET>`, `AWS_PROFILE=<본인 프로필>`로 실행한다. 키는 `~/.aws`에만 두고 레포의 `.env`에 넣지 않는다. 파일은 `local/` 아래에 올라간다.

## 테스트

- S3를 호출하는 테스트는 `test-support`의 `S3MockTestcontainersConfig`를 `@Import` 한다(로컬과 같은 S3Mock 이미지).
- `@IntegrationTest`는 S3 설정에 가짜 값만 넣어 `S3FileStorage`를 주입받을 수 있게 하고, 컨테이너는 띄우지 않는다.
- `hapbang.storage.s3.bucket`이 없으면 S3 빈을 만들지 않는다. 직접 `@SpringBootTest`를 쓰는 테스트는 S3를 쓰지 않는 한 설정이 필요 없다.
- 이 조건은 동적 속성(`@DynamicPropertySource`)보다 먼저 평가된다. 그래서 직접 `@SpringBootTest`를 쓰면서 S3를 쓰는 테스트는 버킷을 `properties`에도 넣는다(`@IntegrationTest`는 이미 넣음).
- 테스트용 객체는 `S3FileStorage.upload`로 올린다.
- 내려받기 URL(`presignDownload(key, expiry, 파일명)`)은 URL로 GET해 응답 헤더를 확인한다. S3Mock 5.2.3은 `response-content-disposition`을 응답 헤더로 돌려준다. 한글 파일명은 Spring 7 `ContentDisposition`이 `filename="___"; filename*=UTF-8''…`로 만든다.
- 대용량 업로드 확인(`@Tag("large-upload")`)은 `check`에서 빠져 있다. SDK·HTTP 클라이언트를 바꿨으면 `./gradlew :member-app:largeUploadTest :lecture-app:largeUploadTest`로 실행한다. 힙 256MB에서 힙의 2배 본문을 올리며, 본문을 메모리에 모으면 OOM으로 실패한다.
