# 추천 리랭킹 설정 결정 (#948, #867 2단계)

챗봇 추천 버튼 경로(#720)의 LLM 리랭킹 설정을 더미 데이터 평가로 정한 기록이다(2026-11-15). 값은 `apps/auxiliary-app/src/main/resources/application-prod.yaml`에 근거 주석과 함께 있다. 평가 도구와 실행 방법은 [`apps/auxiliary-app/README.md`](../../apps/auxiliary-app/README.md) "리랭킹 평가 (#867 2단계, #948)"에 있다. 가중치 결정은 [`recommend-weights.md`](recommend-weights.md)에 있다.

**더미 데이터 기준이다.** 실사용 데이터(추천 카드 클릭 등)가 쌓이면 같은 방법으로 다시 본다.

## 1. 설정과 결정한 값

버튼 경로는 이렇게 돈다.

```
관심사 문장 → 쿼리 확장(LLM, 비슷한 표현 최대 3개) → 원문·표현 임베딩 평균
→ 맞춤 후보 풀 20개(코드 점수 순서) → LLM 리랭킹(풀에서 5개를 골라 순서와 이유)
```

### 리랭킹 (`hapbang.chatbot.recommend.rerank.*`)

| 키 | 뜻 | 전 | prod 결정 | 바뀜 |
|---|---|---|---|---|
| `taste` | 리랭킹 프롬프트에 넣는 요청 회원 정보. `none`은 후보만, `public`은 본인이 이번에 쓴 관심사와 인플루언서의 공개 프로필(분야·자기소개) | none | **public** | 바꿈 |
| `temperature` | 리랭킹 호출에만 싣는 온도. 비우면 공급자 설정(prod 0.2) | 비움(0.2) | **0** | 바꿈 |
| `timeout` | 리랭킹 한 번의 시간 상한. 넘으면 코드 순서로 답한다 | 12s | **15s** | 바꿈 |
| `enabled` | 끄면 코드 순서 5개에 이유만 받는다 | true | true | 유지 |
| `model` | 비우면 공급자 설정(prod gpt-4o-mini) | 비움 | 비움 | 유지 |
| `pool-size` | LLM에게 보여 주는 후보 수 | 20 | 20 | 유지(재지 않음) |

`public`이어도 구매·장바구니·리뷰·함께 출연한 상대·회원 ID는 넣지 않는다. 넣을 취향이 없으면(관심사 없는 일반 회원) 순서를 바꾸지 않고 코드 순서 5개에 이유만 받는다.

### 쿼리 확장 (`hapbang.chatbot.recommend.query-expansion.*`)

바꾸지 않았다(`timeout` 5s, `max-expansions` 3). 아래 결정 4 참고.

`ProdRecommendWeightsTest`(auxiliary-app)가 prod 파일의 리랭킹 값을 설정 record에 묶어 확인하고, 모르는 키(오타)가 있으면 실패한다.

## 2. 결정한 것

1. **취향 `none` → `public`.** 취향 없이 리랭킹하면 끌어올림과 밀어냄이 비슷해(강의 6.0 / 6.7) 코드 순서와 같거나 조금 나빴다(80명 강의 0.346 → 0.317, 인플루언서 0.188 → 0.188). 공개 취향을 주면 강의 0.375, 인플루언서 0.217로 3회 모두 코드 순서보다 높았다. 확인용 20명에서 인플루언서는 다시 좋아졌고(0.30 → 0.40), 강의(관심사 있음)는 지금 운영과 같았다(아래 결정 5).
2. **넣을 취향이 없으면 순서를 바꾸지 않는다.** 관심사 없는 강의 회원을 취향 없이 리랭킹하면 조정용(0.338 → 0.329)과 확인용(0.40 → 0.30) 모두 코드 순서보다 나빴다. `public`은 이 회원들에게 코드 순서를 그대로 보낸다.
3. **온도 0.** 리랭킹은 고르기라 흔들림의 이득이 없다. 80명에서 강의 0.375 → 0.383, 인플루언서 0.217 → 0.225로 같거나 조금 높고, 3회 범위가 좁아졌다(인플루언서는 3회가 같았다). 차이는 1명 정도라 점수보다 안정성을 근거로 정했다.
4. **쿼리 확장은 유지.** 80명에서 확장을 끈 쪽이 0.400으로 가장 높았지만(같은 풀 코드 순서 0.350) 차이가 2명 정도다. 평가 관심사 문장은 취향 분야에서 만든 또렷한 문장이라 확장의 몫(흐릿한 문장을 넓히기)이 평가에 잡히지 않는다. 확인용 20명에서는 확장 유무가 같았다(0.35). 나중 업그레이드 후보로 둔다.
5. **확인용 20명 1회: 강의는 개선을 다시 보지 못했다.** 강의(관심사 있음)는 공개 취향 + 온도 0이 0.35로 지금 운영(0.35)과 같고 코드 순서(0.40)보다 1명 적었다. 20명은 1명이 5%p라 우연 범위로 보고, 조정용 3회가 모두 코드 순서보다 높았던 것과 어느 줄에서도 지금 운영보다 나쁘지 않은 것을 근거로 켰다.
6. **시간 상한 12s → 15s.** 평가 최대 지연이 11.6s로 12s에 가까웠다(4명 동시 실행). 쿼리 확장 5s를 더해도 버튼 한 번 20s로 목표 25s 안이다. 운영 fallback 지표를 보고 다시 본다.
7. **OpenAI 구조화 출력 스키마 수정.** 첫 시험 실행에서 리랭킹 요청이 모두 `400`으로 거절됐다. OpenAI strict 스키마는 객체의 모든 필드가 `required`여야 하는데, Spring AI가 `@Nullable` 필드를 빼고 보냈다. 응답 레코드에 `@JsonProperty(required = true)`를 달고 스키마 테스트(`StructuredOutputSchemaTest`)를 더했다. 이 평가 전까지 구조화 출력은 Ollama에서만 확인했다.

## 3. 평가 기록

**방법**

- 데이터·임베딩·정답 숨기기는 가중치 평가와 같다(시드 867 더미 데이터, OpenAI `text-embedding-3-small`). 가중치는 prod 값이다(강의 β 0.2, 인플루언서 β 0.1).
- 리랭킹 모델: `gpt-4o-mini`. 운영 버튼 경로 클래스를 그대로 부르고, **같은 후보 풀의 코드 순서**와 비교한다.
- 조정용 80명 3회로 고르고, 확인용 20명은 마지막에 1회만 쟀다.
- 지표: hit@5, 끌어올림(코드 순서 5위 밖 정답 → 5위 안), 밀어냄(5위 안 정답 → 밖), fallback, 리랭킹 지연·토큰.
- 비용: 80명 전체 약 $0.62(LLM 2,640회, 35분), 확인용 약 $0.04. 버튼 한 번의 리랭킹은 입력 약 1,300~1,600 / 출력 약 150토큰이다.

**조정용 80명 × 3회** (hit@5 평균(범위) / 같은 풀 코드 순서 / 끌어올림·밀어냄은 회차 평균)

| 방식 | 대상 | hit@5 | 코드 순서 | 끌어올림 / 밀어냄 | 지연 평균·최대 |
|---|---|---|---|---|---|
| 취향 없음 | 강의 신호만 | 0.329 (0.325~0.338) | 0.338 | 6.0 / 6.7 | 3.5s · 9.2s |
| 취향 없음 | 강의 신호+관심사 | 0.317 (0.300~0.338) | 0.346 | 4.3 / 6.7 | 3.6s · 7.0s |
| 취향 없음 | 인플루언서 | 0.188 (0.188~0.188) | 0.188 | 8.0 / 8.0 | 3.3s · 5.7s |
| 공개 취향 | 강의 신호+관심사 | 0.375 (0.363~0.388) | 0.346 | 9.7 / 7.3 | 3.7s · 8.1s |
| 공개 취향 | 인플루언서 | 0.217 (0.200~0.225) | 0.188 | 10.3 / 8.0 | 3.7s · 10.4s |
| **공개 취향, 온도 0** | 강의 신호+관심사 | **0.383** (0.375~0.388) | 0.346 | 10.3 / 7.3 | 3.7s · 7.9s |
| **공개 취향, 온도 0** | 인플루언서 | **0.225** (0.225~0.225) | 0.188 | 11.0 / 8.0 | 3.9s · 11.6s |
| 공개 취향, 쿼리 확장 없음 | 강의 신호+관심사 | 0.400 (0.400~0.400) | 0.350 | 11.7 / 7.7 | 4.0s · 9.1s |

**확인용 20명 × 1회**

| 방식 | 대상 | hit@5 | 코드 순서 | 끌어올림 / 밀어냄 |
|---|---|---|---|---|
| 취향 없음 | 강의 신호만 | 0.30 | 0.40 | 0 / 2 |
| 취향 없음 | 강의 신호+관심사 | 0.35 | 0.40 | 0 / 1 |
| 취향 없음 | 인플루언서 | 0.20 | 0.30 | 2 / 4 |
| **공개 취향, 온도 0** | 강의 신호+관심사 | **0.35** | 0.40 | 0 / 1 |
| **공개 취향, 온도 0** | 인플루언서 | **0.40** | 0.30 | 3 / 1 |
| 공개 취향, 쿼리 확장 없음 | 강의 신호+관심사 | 0.35 | 0.35 | 1 / 1 |

**사람이 읽은 것** (공개 취향, 강의 신호+관심사, 1회차 10명)

- 관심사와 맞는 정답을 끌어올렸다: 코드 순서 7위 → 1위("게임 방송을 시작해 보고 싶어요"), 17위 → 3위("알고리즘 문제를 잘 풀고 싶어요").
- 관심사를 글자 그대로 따라 밀어냈다: "건강한 도시락을 싸고 싶어요"에서 운동 강의 5개를 골라 코드 순서 2위 요리 강의 정답이 빠졌다.
- 풀에 맞는 후보가 없으면 이유가 억지스럽다: "웹 서비스를 직접 만들고 싶어요"에 여행 강의를 고르고 "웹 서비스와 관련된 일정 관리"라고 썼다. 프롬프트 개선 후보다.
- 못 맞힌 회원 대부분은 정답이 후보 풀 20개 밖이었다. 리랭킹으로는 고칠 수 없다.

**한계**

- 정답은 "숨긴 구매·출연 하나를 맞히는가"뿐이다. 관심사에는 맞지만 정답과 다른 추천은 점수가 낮게 나온다.
- 평가 관심사 문장과 인플루언서 공개 프로필은 더미 데이터라 실제보다 또렷하다. 공개 취향의 이득은 부풀려졌을 수 있다.
- 지연은 회원 4명을 동시에 돌린 값이다. 운영 지연은 배포 뒤 지표로 본다.
