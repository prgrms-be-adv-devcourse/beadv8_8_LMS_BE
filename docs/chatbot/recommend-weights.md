# 추천 가중치 결정 (#867)

챗봇 강의·인플루언서 추천의 가중치를 더미 데이터 평가로 정한 기록이다(2026-11-14). 값은 `apps/auxiliary-app/src/main/resources/application-prod.yaml`에 근거 주석과 함께 있다. 평가 도구와 실행 방법은 [`apps/auxiliary-app/README.md`](../../apps/auxiliary-app/README.md) "추천 가중치 평가 (#867)"에 있다.

**더미 데이터 기준이다.** 실사용 데이터(추천 카드 클릭 등)가 쌓이면 같은 방법으로 다시 본다.

## 1. 가중치와 결정한 값

추천 점수는 두 단계로 만든다.

```
취향 벡터 = 신호 강의 벡터의 가중 평균        ← 신호 가중(구매·장바구니·별점 보정)
            (관심사가 있으면) (1−α)·신호 + α·관심사
최종 점수 = (1−β)·유사도 + β·인기(후보 안 0~1)
```

### 강의 (`hapbang.chatbot.recommend.lecture.*`)

| 키 | 뜻 | 전 | prod 결정 | 바뀜 |
|---|---|---|---|---|
| `popularity-weight` (β) | 최종 점수에서 인기(산 회원 수)의 비율 | 0.05 | **0.2** | 바꿈 |
| `interest-weight` (α) | 관심사 문장을 취향에 섞는 비율. 관심사가 있을 때만 쓴다 | 0.3 | 0.3 | 유지 |
| `weights.owned` | 산 강의의 기본 세기 | 1.0 | 1.0 | 유지 |
| `weights.cart` | 장바구니 강의의 기본 세기 | 0.6 | 0.6 | 유지 |
| `weights.rating1` | 1점 리뷰 보정. 세기가 0 이하가 되면 신호에서 뺀다 | −0.5 | **−1.0** | 바꿈 |
| `weights.rating2` | 2점 리뷰 보정 | −0.3 | **−0.6** | 바꿈 |
| `weights.rating3` | 3점 리뷰 보정 | 0 | 0 | 유지(재지 않음) |
| `weights.rating4` | 4점 리뷰 보정 | 0.3 | 0.3 | 유지 |
| `weights.rating5` | 5점 리뷰 보정 | 0.5 | 0.5 | 유지 |
| `signal-limit` | 최근 신호 몇 개까지 쓰나 | 50 | 50 | 유지(재지 못함) |

### 임시값: 평가 없이 정한 값 (#1007)

아래 두 값은 **임시값**이다(더미 데이터 평가 없이 정함). 긴 강의 소개가 제목·주제를 묻어 추천이 어긋나는 문제(#995)를 줄이려고 넣었다. 실제 모델로 전후를 비교하지 않았다. 실사용 데이터가 쌓이면 위 표의 값과 같은 방법으로 다시 본다.

| 키 | 뜻 | 기본값 | prod |
|---|---|---|---|
| `title-weight` (w) | 강의 벡터 = `정규화((1−w)·정규화(글 벡터) + w·정규화(제목 벡터))`(크기 1로 저장: 취향 벡터가 신호 강의 벡터를 정규화 없이 가중 평균하므로, 크기가 다르면 신호 가중치가 강의마다 달라진다). 글은 제목 + 소개 전체 + 목차 제목(그대로), 제목은 같은 공급자 호출에 함께 넣는다. 0이면 제목을 따로 임베딩하지 않는다 | 0 | **0.3** |
| `chat-interest-weight` | 자유 질문 대화의 강의 추천 Tool에서 쓰는 α. 대화에서 직접 말한 요구가 과거 구매보다 앞서게 한다. 위젯·추천 버튼은 위 `interest-weight`(0.3) 그대로다. 정하지 않으면 `interest-weight`를 쓴다 | (없음 = α) | **0.7** |

- **`title-weight`를 바꾸면 모든 강의를 다시 임베딩한다.** 색인 문서의 `text_hash`에 w가 들어간다(w가 0이면 #1007 전과 같은 해시). 배포 뒤 정합 점검(기동 직후 한 번, 매시 :50)이 해시가 다른 강의를 모두 색인 요청으로 적고, 색인 실행기가 5초마다 50개씩 처리한다. 걸리는 시간은 대략 `강의 수 / 50 × (5초 + 한 회차 시간)`이고, 그동안 옛 벡터와 새 벡터가 섞여 추천 순서가 조금 흔들린다. 한 회차의 공급자 호출 수는 늘지 않는다(입력만 제목 수만큼 는다).
- **따라잡았는지 확인하기**(배포 뒤, 그리고 되돌린 뒤):
  1. 기동 점검 로그 `강의 추천 색인이 사본과 달라 색인을 요청했다 trigger=startup, requested=N`의 N이 강의 수와 비슷한지 본다(전체 요청이 적혔다).
  2. 끝나지 않은 강의 요청이 0이 될 때까지 본다: `SELECT count(*) FROM chatbot.index_task WHERE index_type = 'LECTURE' AND done_at IS NULL`. 그동안 지표 `hapbang.chatbot.index.tasks{type=LECTURE,result=done}`가 늘고, 다 끝나면 멈춘다. `result=failed`가 늘거나 `[CHATBOT_INDEX_TASK_STUCK]`이 나오면 임베딩 공급자 장애를 본다.
  3. 다음 매시 :50 점검에서 위 로그(`trigger=scheduled`)가 나오지 않으면 모든 문서의 해시가 지금 w와 맞는다.
- **롤링 배포가 겹치는 동안**: 새 pod가 Ready가 될 때까지 옛 pod(다른 w)가 함께 돈다. 그사이 옛 pod의 실행기가 요청을 가져가면 옛 w의 벡터·해시로 다시 쓸 수 있다. 그 강의는 다음 :50 점검이 어긋남으로 보고 다시 요청하므로 늦어도 한 시간 안에 맞춰진다.
- **되돌리기**: `title-weight: 0`으로 배포하면 해시가 #1007 전 값으로 돌아가 다시 전체 색인되고, 벡터도 #1007 전과 같아진다. `chat-interest-weight`는 키를 지우면 위젯과 같은 0.3이 된다.
- **`chat-interest-weight` 0.7과 2장 2번의 평가**: 위 평가(3장 2회차)에서 α 0.7은 0.3보다 조금 나빴다(신호+관심사 hit@5 0.338 < 0.350, 상위 20개 안 정답 0.500 < 0.563). 그래도 Tool 경로만 0.7로 둔 이유는 다음과 같다.
  - 2장 2번이 0.3을 유지한 근거 하나는 "버튼 경로는 LLM이 상위 20개에서 다시 고르므로 20개 안 정답이 중요하다"였다. Tool 경로는 리랭킹 없이 상위 5개를 그대로 보여 주므로 이 근거가 바로 적용되지 않는다.
  - 대화에서 사용자가 직접 말한 요구는 위젯 관심사 칸보다 지금 원하는 것에 가깝다고 보고, 평가 손해를 감수하고 과거 구매보다 앞세웠다.
  - 반대 방향의 단서도 있다. 더미 관심사 문장은 취향 분야에서 바로 만들어 실제보다 정확하므로, 더미 평가는 α를 올린 이득도 손해도 실제와 다를 수 있다. 0.7이 맞는 방향인지는 실제 모델·실사용 데이터로 다시 본다. 그때까지 임시값이다.
- 유사도 분포는 지표 `hapbang.chatbot.recommend.similarity{type=LECTURE|INFLUENCER, path=widget|chat|button}`(0.05 간격 구간)로 본다. 경로마다 α(위젯·버튼 0.3, Tool 0.7)와 후보 풀 크기(위젯·Tool은 추천 수, 버튼은 20)가 달라 분포도 다를 수 있어 나눠 센다. 판매자당 상한·순위로 자르기 전의 후보 점수라 화면에 나간 추천만의 점수는 아니다. 하한은 두지 않았다. 분포를 본 뒤 경로마다 따로 정한다.

바꾼 값과, 1·2점 보정의 전제인 `owned`·`cart`를 `application-prod.yaml`에 둔다. 나머지는 코드 기본값이고, local(Ollama) 값은 출발값 그대로다. `ProdRecommendWeightsTest`(auxiliary-app)가 prod 파일을 설정 record에 묶어 값을 확인하고, 모르는 키(오타)가 있으면 실패한다.

## 2. 결정한 것

1. **강의 β 0.05 → 0.2.** 기본 데이터에서 80명 hit@5가 4명 늘었다(0.288 → 0.338). 인기와 무관하게 구매하는 변형 데이터에서는 0이 가장 좋아 β는 데이터 가정에 흔들리는 값이다. 두 데이터에서 각 값이 잃는 인원을 합하면 0.2가 가장 적었다(5명, 0.05·0.1은 11~12명). 0.25는 0.2보다 1명 많았지만 같다고 보고(2명 이하) 다양성이 나은 0.2를 골랐다. 0.3부터는 두 데이터 모두 나빠졌다.
2. **강의 α 0.3 유지.** 0~0.7 모두 hit@5 차이가 2명 이하다. 0.5는 nDCG@5가 높았지만 상위 20개 안 정답이 3명 줄었다. 리랭킹은 상위 20개 안에서만 고르므로 20개 안 정답을 더 중요하게 봤다. 더미 관심사 문장은 취향 분야에서 바로 만들어 실제보다 정확하므로 α를 올리는 이득은 부풀려졌을 수 있다.
3. **장바구니 0.6 유지.** 0~1.0 중 0.6이 두 줄 모두 가장 좋았다. 0이면 3명 줄어, 장바구니는 쓸모 있는 신호다.
4. **1점 −0.5 → −1.0: 1점 준 강의는 취향에서 뺀다.** 신호 세기 = 기본 + 별점 보정이고 0 이하면 신호에서 빠지므로, 구매 1.0 + 1점 −1.0 = 0이라서 빠진다. 이 전제 때문에 prod yaml에 `owned: 1.0`·`cart: 0.6`도 함께 적고, 바인딩 테스트(`ProdRecommendWeightsTest`)가 구매 + 1점 ≤ 0과 구매 + 2점 = 0.4를 확인한다. 출발값은 "샀다 = 그 주제에 관심 있다"를 앞세워 별점이 구매를 뒤집지 못하게 했다(1점이어도 세기 0.5). 1점은 그 분야에 대한 불호일 수 있다고 보고 바꿨다. hit@5는 같지만, 1점 리뷰가 있는 조정용 10명 전원의 상위 20개가 바뀌었고 상위 5개가 바뀐 5명 중 3건은 1점 준 분야의 강의가 빠지고 취향 분야 강의가 들어왔다. 나빠진 회원은 없었다.
5. **2점 −0.3 → −0.6: 약하게 남긴다.** 2점은 분야보다 그 강의(영상)에 대한 실망일 수 있어, 주제 관심은 세기 0.4로 남긴다. −1.0(빼기)도 나빠진 회원이 없었지만, 2점 리뷰는 9건·바뀐 회원 3명이라 근거가 약해 설계 판단으로 정했다.
6. **4·5점 0.3·0.5 유지.** 9조합 모두 2명 이하 차이다. 가산은 취향 분야 안의 순서만 바꾼다. 4점 0.6은 신호+관심사 줄에서 2명 나빠졌다.
7. **`signal-limit` 50 유지.** 더미 회원은 신호가 최대 12개라 상한이 걸리지 않아 잴 수 없다.
8. **인플루언서 상대 가중 0.5 유지.** 다섯 값 중 hit@5·nDCG@5가 가장 높다. 0.75 이상은 상대의 분야가 섞여 20개 안 정답이 8~12명 줄었다.
9. **인플루언서 β 0.2 → 0.1. 채택 규칙의 예외다.** hit@5는 0.2와 같다(기본 데이터 0.188 → 0.188, 변형 데이터 0.175 → 0.163으로 1명 적음). 그래서 "hit@5가 2명보다 많이 좋아야 바꾼다"는 규칙으로는 바꿀 수 없다. 바꾼 근거는 recall@20이다(기본 데이터 0.500 → 0.613, 9명 증가, 변형 데이터 0.600 → 0.650).
   - 예외로 본 이유: 버튼 경로(#720)는 LLM이 맞춤 후보 20개에서 5개를 다시 고른다. 그래서 위젯의 상위 5개만큼 상위 20개 안 정답도 중요하다고 봤다(강의 α를 정할 때도 같은 기준을 썼다).
   - 0이 아닌 이유: 기본 데이터에서 hit@5가 가장 높은 값은 0(0.225)이지만, 변형 데이터에서는 0과 0.1이 같고, 두 데이터를 합치면 0과 0.1이 2~3명 차이로 같다. 0이면 받은 별점이 순서에 전혀 쓰이지 않아 0.1을 골랐다.
   - 한계: 이 근거는 리랭킹이 상위 20개 안 정답을 5위 안으로 끌어올린다는 데 기댄다. 그 효과는 #867 2단계에서 재므로 그 전까지는 검증되지 않았다. 리랭킹이 효과가 없거나 꺼지면 이 결정을 다시 본다.
10. **인플루언서 인기 계산식은 재지 않았다.** β 0.1이면 인기 전체가 점수의 10%라 계산식의 영향이 작다.
11. **확인용 20명 1회: 통과.** 정한 값으로 강의 0.400(신호만)·0.350(신호+관심사), 인플루언서 0.300으로 80명 결과보다 낮지 않았다(기준: 15%p 넘게 낮으면 80명에 맞춘 값으로 본다). 20명은 1명이 5%p라 높게 나온 것은 우연 범위다.

## 3. 평가 기록

**방법**

- 데이터: 시드 867 더미 데이터(분야 8개, 강의 120개, 강의 회원 100명, 인플루언서 100명). 회원 신호의 20%는 취향 밖 잡음이다. 정답은 강의 회원마다 구매 하나, 인플루언서마다 함께 완료한 상대 하나를 숨긴 것이다.
- 임베딩: 운영과 같은 OpenAI `text-embedding-3-small`(1536차원). 운영 추천 UseCase를 그대로 부른다.
- 조정용 80명으로 값을 고르고, 확인용 20명은 마지막에 한 번만 잰다.
- 지표: hit@5(정답이 추천 5개 안), nDCG@5(정답이 위일수록 높음), recall@20(정답이 맞춤 후보 20개 안), 상위 5개의 서로 다른 수(쏠림).
- 채택 규칙(결과 전에 정함): hit@5가 2명(0.025)보다 많이 좋아야 바꾼다. 그 이하는 "차이 없음"으로 지금 값을 둔다.
- 변형 데이터(`dataset-flipped.json`): 강의는 인기와 무관하게 사고, 출연 상대는 평판(품질³)에 비례해 고른다. 정답 인플루언서의 평균 받은 별점이 기본 3.59(전체 3.72보다 낮음), 변형 3.97(전체 3.77보다 높음)이다.

**한계**

- 정답은 "숨긴 구매·출연 하나를 맞히는가"뿐이다. "싫어한 분야가 덜 나온다" 같은 개선은 점수에 잡히지 않아, 평가 도구에 추천이 바뀐 회원과 분야를 찍게 해서 봤다(4-2).
- β는 데이터 가정(인기가 정답과 관련 있나)에 크게 기대서 두 데이터로 쟀다. 실제 서비스가 어느 쪽인지는 실사용 데이터로만 알 수 있다.
- 리랭킹(LLM이 상위 20개에서 다시 고름)을 켠 버튼 경로의 효과는 이 평가에 없다. #867 2단계에서 잰다. 강의 α 유지와 인플루언서 β 0.1은 "상위 20개 안 정답이 많을수록 리랭킹이 끌어올릴 여지가 크다"는 가정에 기대므로, 2단계 결과가 나오면 다시 본다.
