# 커밋 메시지 규칙

## 1. 커밋 유형

커밋 유형은 영어로, 첫 글자를 대문자로 쓴다.

| 커밋 유형 | 의미 |
| --- | --- |
| `Feat` | 새로운 기능 추가 |
| `Fix` | 버그 수정 |
| `Docs` | 문서 수정 |
| `Style` | 코드 formatting, 세미콜론 누락, 코드 자체의 변경이 없는 경우 |
| `Refactor` | 코드 리팩토링 |
| `Test` | 테스트 코드, 리팩토링 테스트 코드 추가 |
| `Chore` | 패키지 매니저 수정, 그 외 기타 수정 ex) .gitignore |
| `Design` | CSS 등 사용자 UI 디자인 변경 |
| `Comment` | 필요한 주석 추가 및 변경 |
| `Rename` | 파일 또는 폴더 명을 수정하거나 옮기는 작업만인 경우 |
| `Remove` | 파일을 삭제하는 작업만 수행한 경우 |
| `!BREAKING CHANGE` | 커다란 API 변경의 경우 |
| `!HOTFIX` | 급하게 치명적인 버그를 고쳐야 하는 경우 |

## 2. 제목과 본문

- 제목과 본문은 빈 행으로 나눈다.
- 커밋 유형 뒤의 제목과 본문은 한글로 써서 내용이 잘 전달되게 한다.
- 본문에는 변경한 내용과 이유를 적는다. 어떻게보다는 **무엇**과 **왜**를 설명한다.
- 자신의 코드를 다른 사람이 바로 파악할 수 있다고 생각하지 않는다.

## 3. 제목

- 첫 글자는 대문자로 쓰고, 끝에 `.`을 붙이지 않는다.
- 영문 기준 50자 이내로 쓴다.

## 4. 여러 항목

여러 항목이 있으면 글머리 기호로 나눈다.

```
- 변경 내용 1
- 변경 내용 2
- 변경 내용 3
```

## 이슈 번호

티켓 하나를 PR 여러 개로 나눌 때 커밋에 `Ref #N`을 쓰는 방법은 [작업 흐름](git-workflow.md)의 "PR"에 있다.
