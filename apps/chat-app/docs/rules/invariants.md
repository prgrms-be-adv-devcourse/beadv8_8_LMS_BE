# 불변식

고도화 작업 중에도 바꾸지 않는 현재 동작이다. 바꿔야 하면 먼저 질문한다.

- 메시지 순번(`roomSequence`)은 방 안에서 유일하고 증가하며, 메시지·outbox 저장과 참여 상태 변경 사이의 정합성을 보장한다. 초기 구현은 짧은 방 단위 `PESSIMISTIC_WRITE` 트랜잭션을 사용한다. 잠금 방식 자체를 영구 불변식으로 고정하지 않으며, 대체 구현은 재전송·롤백·참여 세대·복구 계약을 동일하게 검증해야 한다(사용자 결정, 2026-10-29; 설계 문서 4.6·4.7).
- 같은 참여 안의 같은 `clientMessageId` 재전송은 새로 저장하지 않고 기존 메시지를 보낸 사람에게만 다시 보낸다. 상대 알림·안 읽은 수를 다시 올리지 않는다 (#261, #311).
- 참여자는 `visibleFromSequence` 이후 메시지만 본다. 옛 참여 세대(`participationVersion`)의 요청·전달은 무시한다.
- 읽음 순번은 조건부 UPDATE로만 올리고 줄이지 않는다.
- 실시간 전달은 DB 커밋 뒤에 한다. 전달 실패는 전송 실패가 아니다. 보낸 사람에게 실패로 알리지 않는다.
- 방 단위 topic을 열지 않는다. 회원별 큐(`/user/queue/chats/...`)로만 보내고, `ChatStompInterceptor`의 구독·전송 경로 제한을 유지한다.
- 회원 복제본(`ChatUser`)은 가입 이벤트로만 만들고, 변경 이벤트는 `memberVersion`이 더 클 때만 반영한다.
