# 범위

채팅 앱 작업의 포함·제외 범위다.

- chat-app은 **replica 1개**를 기준으로 설계·구현·테스트·배포한다(사용자 결정, 2026-10-29). 여러 사용자와 동일 회원의 여러 WebSocket 연결은 한 앱에서 처리한다. 복수 replica 배치·전달·연결 종료 시험은 이번 범위에서 제외한다.
- **Redis Streams를 이번 전환 범위에 포함한다**(2026-10-29 사용자 변경 결정). outbox 적재·그룹 소비·ACK·pending 회수·실패 격리·안전한 보존·Redis 유실 재구성을 Pub/Sub·로컬 STOMP와 함께 설계·검증한다. 알림 모듈의 Kafka 대체는 포함하지 않는다.
- **누적 수신 커서와 클라이언트 ACK를 이번 범위에 포함한다**(2026-10-29 사용자 결정). PostgreSQL의 기존 참여 행에 수신 순번을 추가하고, ACK 병합·세대 검증·기기별 이력 복구를 구현·검증한다(설계 문서 4.4). 메시지별·사용자별 수신 이력 행과 서버 기기별 수신 테이블, 새 DB 도입은 제외한다. 기존 읽음 위치 정책을 유지한다. 모집용 단체방의 메시지별 안 읽은 사람 수는 2026-11-02 결정으로 추가하며 기술 계약은 Q36에서 확정한다.

- 현행 구현은 1:1 채팅이며, **이번 고도화의 설계·구현 범위에 단체(그룹) 채팅을 포함한다**(사용자 결정, 2026-10-29). `GROUP` 타입·도메인·API·마이그레이션·FE·관리자 기록·테스트를 작업 범위에 넣는다. 단체채팅 포함 여부를 다시 승인받거나 후속 과제로 미루지 않는다.
- 출연 알림(`AppearanceNotificationEventListener`)은 알림 모듈·FE 이관이 끝나기 전에 제거하지 않는다 (설계 문서 5.5).
- 모집용 단체방의 확정 정책(2026-11-02)은 설계 3장과 정책 8장을 따른다. 출연 연동·부분 초대·강퇴/재초대·읽기 전용·재생성·30일 참여자 조회 만료·호스트 일시 중지·읽음 숫자와 FE/관리자 기록을 포함한다. 메시지/감사 기록의 물리 삭제는 포함하지 않는다. 정원은 실측으로 확정하며 500명은 시험 후보 상한이다.
- 설계 문서 8장의 미정 항목은 추측으로 정하지 않는다. 모집용 방 정책과 Q31~Q38은 확정했고(2026-11-03) 남은 것은 Q12(실측)다. 미정 정책·FE 계약은 해당 구현 전에 확정하고 결과를 설계 문서와 용어·정책에 남긴다. 이미 확정한 사항은 다시 승인받지 않는다.
