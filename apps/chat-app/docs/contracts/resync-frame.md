# 계약 (e): 재동기화 신호 프레임과 수신 메타데이터 (#419, Q11 초안)

실시간 경로가 끊겼다 복구됐을 때 FE에 이력 재동기화를 알리는 계약이다. 설계는 [설계 문서](../final-design.md) 4.2·4.4다. **FE와 합의했다**(2026-10-29, FE beadv8_8_LMS_FE#127). 형식을 바꾸면 FE 세션에 먼저 알린다.

## 재동기화 신호

- 목적지: `/user/queue/chats/sync` (회원별 큐. 기존 `ChatStompInterceptor`의 `/user/` 구독 규칙 안이다)
- 보내는 때: chat-app의 Redis 구독이 끊겼다가 다시 연결된 직후, 그 앱의 **모든 로컬 연결**에 한 번씩 보낸다.

```json
{ "type": "RESYNC", "reason": "REALTIME_RESUBSCRIBED", "occurredAt": "2026-10-29T10:00:00" }
```

| 필드 | 값 |
| --- | --- |
| `type` | `RESYNC` |
| `reason` | `REALTIME_RESUBSCRIBED`(구독 복구). 이후 사유를 추가할 수 있으므로 FE는 모르는 값도 재동기화로 처리한다 |
| `occurredAt` | 서버 시각 |

FE 처리: 방 목록과 열어 둔 방의 이력을 자기 확인 위치부터 다시 대조한다. 이 신호도 유실될 수 있으므로 FE의 주기적 대조를 유지한다(주기는 Q12).

## 메시지·알림 프레임의 참여 세대

- `/user/queue/chats/messages`, `/user/queue/chats/notifications` 프레임에 STOMP 헤더 `participation-version`을 붙인다. 값은 그 수신자의 메시지 저장 당시 참여 세대다.
- payload(`ChatMessageResponse`, `ChatNotification`)는 바꾸지 않는다.
- FE는 헤더 값이 그 방에서 알고 있는 현재 세대보다 낮으면 프레임을 적용하지 않는다. 더 높으면 그 프레임은 적용하지 않고, 그 탭의 옛 세대 이력·보내는 중 표시·확인 위치를 버린 뒤 방 목록·이력을 새로 받는다(그 메시지는 새 세대 이력으로 들어온다). 헤더가 없으면(전환 전 서버) 기존처럼 적용한다.
- FE는 `/user/queue/chats/notifications`를 구독하지 않는다(같은 메시지를 메시지 큐로 받는다). 서버는 알림 큐 전송을 유지한다.

## FE 처리 (합의 내용)

- `RESYNC`를 받으면 사유와 관계없이 방 목록과 열어 둔 방의 이력을 바로 대조한다. 주기 대조(잠정 30초 ±20%)는 계속 돈다.
- 재연결: 정책 종료 2종을 뺀 종료는 3초부터 두 배씩 최대 30초, 매번 0~1초 무작위 대기를 더한다. 연결되면 전체 재조회와 대조를 한다.
- 전송 결과 확인: 10초 안에 같은 `clientMessageId` 응답이 없으면 최신 2페이지에서 찾는다. 없으면 "결과 미확인"으로 두고 같은 ID 재시도를 제공한다. 소켓 단절은 실패가 아니라 결과 미확인이다.

## 연결 종료 사유

| 종료 | 의미 | FE |
| --- | --- | --- |
| `1008` + `LOGGED_OUT` | 로그아웃(기존) | 재연결하지 않는다 |
| `1008` + `CHAT_NOT_ALLOWED` | 정지·강등·탈퇴(기존, 이제 RECHECK_USER로도 닫힌다) | 재연결하지 않는다 |
| 그 밖의 종료(느린 수신자의 송신 버퍼 초과 포함) | 서버가 연결을 유지할 수 없음 | backoff·jitter로 재연결하고 재동기화한다 |
